# S04 / #17 — Source management, discovery and OPML drafts

## Spec review and frozen contract
One owner's existing local control API provides the source-picker data and actions used by the retained mockup: recommendations, URL/feed discovery, explicit source classification, compatible subscription assignment, actual preview, enable/pause/edit/delete, bounded OPML draft import. This is a backend issue, not U02's Swift UI. R02/R03 and issue17 acceptance are binding; no live account, paid model, Telegram delivery, dynamic plugin, arbitrary scraping, or mockup health migration.

Acceptance:
- Catalogue includes accepted world/Japan/Australia/China/electronics/AI and the already-known adult reference; CNN/Yahoo Japan/Zaobao retained. It distinguishes feed/API vs unimplemented website, section scope labels, partition, recommendation origin and dated evidence; every item still requires actual preview. No availability/freshness from mockup badges.
- HTTPS URL identification reads bounded public data with F03. Direct RSS/Atom produces a choice; HTML head alternate RSS/Atom links (up to20) produce choices, never automatically select first or fetch all. Unknown website saved as disabled draft. GitHub/HF reuse S03 supported URL parser; HF organization page maps explicitly to /models?author=. X URL returns X-management destination, not a feed. Returned candidates are unverified metadata until explicit preview.
- Create/update requires explicit stable source ID/name/URL/kind/partition/category IDs and config revision; missing classification remains disabled and unassigned. Supported type selection alone does not establish health. Enable requires classified categories, implemented connector and latest successful preview for current source URL/partition/kind, not merely catalogue inclusion. Empty/stale/no-eligible valid parsed feeds can enable with visible freshness status; transport/parser/config-changed failures cannot. No fresh timestamp fabrication. Web/draft remains unenableable until S02 implements its adapter.
- Preview of a saved classified source (including disabled) uses S01/S03 collectors, retains evidence/health and returns at most10 actual entries with original publisher/title/link, real publication/update/fetch timestamps, raw invalid time reason, language, excerpt scope and content hash. Freshness eligibility shown separately; no LLM, downloads or sends. Unclassified sources cannot be previewed into either partition. Unknown web returns unsupported, no generic article scraper.
- Source can be assigned to multiple compatible subscriptions, adding category associations in the same mutation. Subscription source_ids=[] currently means inherit category: adding an explicit source materializes existing inherited sources plus chosen source, preserving selection instead of silently replacing it. Assignment never changes schedule, model, language, style or targets. Catalogue section labels and distinct feeds select domestic/entertainment/product/model scopes; semantic weighting/selection belongs to subscription editor/Q01 and M04, not a new source-specific scheduler.
- Editing partition/categories with incompatible existing subscription references rejects atomically; no silent cross-partition move. Editing URL/kind/partition forces disabled until new preview; old evidence remains historical, inaccessible through current-identity preview. Delete removes explicit refs atomically; if last explicit source removed, affected subscription is disabled and reported for reselection so [] inheritance cannot unexpectedly broaden an active schedule. Inherited source selection naturally loses removed entry. Config CAS prevents lost concurrent updates; only existing Store/CredentialManager save path used.
- OPML input max1MiB UTF8 bytes, max200 feed outlines and2000 total nodes, max16 XML depth, no DTD/entities/includes/network. Recognize nested outline xmlUrl attributes; type rss or absent is accepted, other types ignored. Names plain-text bounded150; ignore OPML owner and credentials fields; unsafe/HTTP/credential URLs rejected per-entry with index/fixed reason, never echo secret URL. Enforce all limits before any config commit; too many current+new sources rejects all. Newly imported sources unclassified, unassigned and disabled. Duplicate imports across repeated calls preserve stable identity and existing preferences, including previously classified sources; match normalized URL for import only and do not reclassify. If identical URL has several partition-specific existing records, skip as existing rather than choose/edit a partition. No empty/duplicate-only save/revision churn. Partial per-entry URL rejection is explicit; XML/limit/CAS failure is all-or-nothing.

## Approach and lifecycle
Add SourceManager around existing Store/CredentialManager; one small source_readiness table (source_id PK, epoch, attempt_id nullable) and no general connector registry. Schema11 initializes existing configured sources as unpreviewed for setup; existing collection/history is unchanged. Each explicit discovery/preview owns a short-lived F03 client and closes on error/cancellation. Existing collectors protect in-flight preview against URL/partition/enable changes. S04-D01 correction: tuple equality alone resurrects old A preview after A→B→A (independent EvidenceStore proof in run). All three existing Store configuration write paths atomically bump a retained source_readiness epoch and clear attempt_id for URL/kind/partition changes, removal or re-add; tombstones persist. Initial source creation records epoch1. Preview captures epoch before collector call and stores successful attempt_id only after rechecking epoch/current source inside the write transaction; a changed epoch returns configuration_changed even if fields reverted. (R17 F1, 0.6.2: a later completed attempt that also succeeded no longer unpins it; "no later failure" stands.) The pinned attempt must also be the latest completed attempt for the current source identity, with current kind, successful snapshot/status and no later failure; enable refuses otherwise. Initial migrated sources need a new explicit preview through this setup API. Existing RSS/API evidence/history/cache semantics remain unchanged. Tests pin A→B→A, deletion/re-add, in-flight ABA, restart and CAS rollback; historical old evidence remains readable but does not authorize enabling. Mutations through source APIs use expected revision and saved latest config; no await/HTTP within DB transaction. Whole config endpoint remains existing advanced validated config API; source-manager health check is setup readiness, scheduler still revalidates runtime routes. No claim that source enable alone makes subscription runnable. Source route-preview returns existing resolve_route explanation/effective/blockers for associated subscriptions, no Keychain reads and no dispatch authority. History/health reuse EvidenceStore.

Discovery accepts a public HTTPS URL only (existing app_config credential rejection + public_url literal-address/local-host rejection, DNS guard at actual dial), <=2048. Same-origin redirects only <=3 consistent with FeedCollector; final URL is displayed, cross-origin redirects explicit error, not guessed rewrite. 2MiB response/30sec, no auth/cookies/ambient proxy. RSS structural validity from existing parse_evidence before format selection; feedparser version inspected only after safe bounded parse, never a filename. HTML discovery uses stdlib HTMLParser, only head links, first valid base href resolves relative links; untrusted titles plain-text, candidate URLs independently validated. No active content or website instructions. Unsupported/malformed XML stays unsupported, DTD rejected; discovery does not persist fetched article data before classification. Failed fetch returns fixed diagnostic, permits user explicitly save unknown draft.

Normalization for idempotency: lowercase scheme/host, strip default443, empty path '/', preserve path case and exact query order/value; no tracking/query deletion, no HTTP upgrade, no trailing path slash collapse. Ordinary create prevents duplicate normalized URL/kind/partition. Import dedupes by normalized URL regardless classification because it never reclassifies existing records. New IDs uuid-based; results report added/existing/rejected indices. OPML is content supplied in RPC, not a filesystem path. Never fetch remote OPML includes or interpret script metadata.
