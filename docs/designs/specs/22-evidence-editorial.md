# M04 / #22 — frozen, evidence-linked editorial editions

## Contract and scope
Produce a structured, frozen brief from this subscription's fresh evidence, using M02's current same-partition primary/backup executor. Translate titles, prose, conflicts and explanatory labels to global news_output_locale (zh-Hans/en/ja). A bad language, malformed or unsupported result fails validation and uses only M02's bounded repair policy; never publish original text as fallback. Counts are maxima, not quotas. Preserve attribution, uncertainty, source conflicts and development stages. Reprints are not independent confirmation; a story may appear in separate subscriptions. No vector database, extra service, arbitrary browsing, delivery, scheduler or new UI. Semantic correctness cannot be guaranteed by deterministic checks; do not claim independent fact checking or perfect language detection.

Read existing ai.py summarize for provenance/prompt lessons, but its original-title renderer and failure fallback do not satisfy this contract. Implement the new configured pipeline in editorial.py; leave prototype APIs for their existing consumers until assigned Q03 integration. Do not rewrite the mockup. Only trusted in-process pipeline calls; no new general model RPC.

## Inputs and evidence freezing
EditorialService.prepare(edition_id, RouteSnapshot, feed_attempt_ids, holds, task_limit) reads S01 EvidenceStore.articles(partition,subscription_id,now,fresh_only=True), never arbitrary caller text. No crossed/missing/unclassified association, stale scope or failed source is accepted as successful evidence. Preserve rejected/failed/no-eligible source coverage separately. Only this issue's RSS/Atom inputs are wired now; S02/S03/X03 integrate their durable evidence through their own accepted connector scopes.

Freeze a bounded pool of up to 200 newest eligible articles (tie by canonical URL/hash), with visible omitted_count. Every retained record has deterministic evidence ID, canonical URL, original publisher/title/excerpt, original publication/update/fetch dates, source language, content hash and actual evidence scope (title_only or rss_excerpt). Exact canonical URL + content snapshot dedupe; same URL changed content is a new snapshot, not a fabricated new publication. Identical retained title/excerpt hashes across mirrors collapse into one candidate with all source links retained and reprint/independence-unknown metadata. No inference that different domains mean independent reporting. Model may combine candidate IDs into one event; each candidate can belong to at most one output item. A basic event key uses the chosen anchor candidate's canonical URL; a content version hashes the cited snapshots. Preserve observed same-anchor changed versions across editions, without making updated_at a new published_at. No global sent-event suppression: subscription/edition identity governs output.

After freeze, M02 receives the exact serialized pool, target locale, item cap and trusted instructions. It never sees credentials, target chat IDs, arbitrary tools or full-source claims. Task ID is derived from subscription+edition, excluding Bot. Evidence hash and schema/operation version bind trusted validator construction. All attempts/repairs reuse this frozen input and task budget. If the pool exceeds the adapter input bound, stop visibly; do not silently trim individual citations.

## Structured output and validation
One explicit JSON schema, locally validated with exact keys/types/length bounds (not provider strictness alone):
- locale, items (0..configured max_items), conflicts (0..5).
- Each item: anchor evidence ID, unique cited evidence IDs, translated title and body, kind (report/individual_claim/rumor), stage (unknown/announcement/patent/prototype/breakthrough/mass_production/model_release/api_available/weights_available), support entries {evidence_id, quote}, entities {source, translated}.
- Each conflict: at least two different cited candidates, translated note, support entries identifying each source's explicit statement. No new URLs, citations or executable fields from the model.
Every quote must be a nonempty bounded exact substring of that candidate's retained title/excerpt; every cited candidate must have support. Numeric tokens in each title/body/note must be present in the associated support after conservative width/separator normalization; no silent numeric conversion. Entity source forms must occur in associated evidence, and translated forms in the item's title/body; source names, account names and product IDs may remain original. Tests reject made-up entity source forms, unsupported figures and assertions with no supporting evidence. These checks do NOT prove entailment of arbitrary prose or catch every undeclared name; trusted instructions require faithful source attribution and omission when uncertain.

Stages/claims are always rendered as attributed source descriptions, never established technical achievements. Prompt distinguishes a rumor, patent, prototype, claim of breakthrough and production; title-only evidence cannot substantiate extra details. Deterministic stage support requires the corresponding stage vocabulary in a cited quote (en/zh/ja), but negation/context remains a known semantic limitation. Unknown is valid, not forced inference. Render localized 'reported/claimed' labels and actual source names/links. No independent-corroboration count or 'verified by multiple sources' claim is generated; known such phrases rejected and the prompt forbids them. Conflicts remain unresolved and attributed; do not invent a conflict from different topics, omissions or dates.

## Language check (IR-05)
Validate every generated title, body and conflict note before saving ready. Model entity mappings NEVER authorize language exemptions, even when the source span is verbatim evidence. Exemptions come only from a small server-owned proper-name lexicon (known brands/products), user-configured short source display names, and a strict bounded product/account identifier grammar (at most 32 characters, no spaces or sentence punctuation, product forms contain letters and digits, account forms start @). An RSS-provided publisher string is untrusted and cannot add a new exemption. Ordinary words or arbitrary evidence spans are not exempt. Remove only these independently selected tokens at exact word boundaries; model-declared entities still undergo grounding checks but do not control language detection. English rejects remaining CJK scripts and needs alphabetic prose. Japanese needs Japanese script and kana in each item's combined title/body, rejects predominantly English sentence prose after permitted names; individual all-kanji short headlines are permitted when body passes. Simplified Chinese needs Han prose, rejects kana and an explicit conservative set of common traditional-only forms; model instructions demand simplified script. Chinese/Japanese shared Han and incomplete traditional-form coverage mean this is a conservative heuristic, not perfect language identification. A visible language_check method/limitations field is local metadata, not a model authority claim. D01 negative fixtures include an entire English sentence declared as one entity and every English word declared as separate entities; neither can remove untranslated prose. Positive fixtures retain known brands, configured short source names and product/account IDs. Other negative gold fixtures cover English prose in zh/ja, Chinese prose in en/ja, kana in zh, mixed-language paragraphs and common traditional forms. Product names/IDs remain permitted. Ambiguous/failed output remains waiting/failed and never falls back to original titles. Fixed labels/headings/empty/coverage notes are a small complete local zh/en/ja dictionary.

## Persistence and lifecycle
Schema8 adds editorial_editions (stable id, subscription, partition, route snapshot, evidence snapshot+refs, created_at, model_task_id, state, result/error JSON) and an index for subscription history. Store frozen edition before ModelRunner.submit; submit is idempotent under a deterministic ID, so a crash between these steps resumes creation before any paid advance. Changed immutable inputs for an existing ID reject. prepare/get do not invoke models. advance rebuilds the trusted validator from stored evidence/schema version, revalidates current route/association/freshness before paid work, then calls M02 once. Empty pool yields a localized no_news edition with zero paid calls.

A completed M02 result is validated again and decorated only with locally sourced citation URLs/timestamps/evidence scopes, localized labels, event/version keys and coverage. Store ready edition atomically. Crash after M02 success but before edition save reuses the durable model result, never charges again. M02 waiting/blocked/refused/unknown/cancelled/stale stays distinguishable; no raw fallback. Changes in language/partition/source membership or evidence aging out make unfinished work stale before further calls. Historical get can inspect frozen old editions; publishing currentness is explicitly checked by the later Q03 stage, not inferred from historical ready. No Telegram sends or sent-state dedupe here.
