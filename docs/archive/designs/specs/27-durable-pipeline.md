# Q01 / #27 — durable edition preparation

## Spec and acceptance

One local backend prepares an edition through collection, editing, media preparation and awaiting delivery. Each stage can be interrupted and resumed independently. An edition links its selected sources, feed attempts, frozen brief, paid attempts and stage events. Collection failure and a successfully checked but empty edition are different outcomes. Pause or cancel one edition independently. A busy/unwritable database must prevent any side effect that has no durable execution record. Reuse already confirmed paid results and preserve unknown attempts and their budget holds across restart; expiry of a job lease never authorizes a second paid request.

The Q01 boundary ends at a durable delivery handoff. Q02 owns binding validation, outbox and actual delivery; Q03 owns schedule, automatic dispatch, clock and generation/rebuild choices; D01/D02 own real media preparation; S05/X03 extend the evidence input. Current mockup is the product reference. No network or paid dispatch starts on migration/startup. Existing legacy receipts, last_slot, collections and briefs remain historical and do not seed runnable jobs. Use one SQLite database and the existing process lock.

## Contract and approach

1. Add SQLite schema 12 using the existing transactional migration and backup. Store pipeline_jobs with stable opaque ID, UNIQUE(subscription_id, account_key, edition_key), frozen RouteSnapshot and budget request, stage, timestamps, pause/cancel flags, lease owner token and expiry, safe error, collection manifest and media outcome. Account key is non-null (empty means aggregate). Validate edition key as bounded canonical string and scope IDs before effects. Idempotent create returns the saved job for the same key and same input; conflicting arguments fail, with no model call. Ignore unrelated configuration revisions when comparing an otherwise identical route. An explicit future rebuild uses a different generation key and keeps the old edition for audit. No time-derived identity yet. Q03 must distinguish logical slot from version, and Q02 must decide whether any part already left before automatic rebuild.
2. Freeze subscription/account, route fingerprint, locale, partition, schedule/style, model profile IDs and current profile generations plus caller-provided holds before the first effect. Derive from current store, not caller-submitted route. Revalidate through existing Store/ModelRunner gates. Q01 additionally rejects dispatch if the original profile generation or full effective route changed, including target-only changes while preparation is pending. This conservative invalidation does not authorize an automatic resend or rebuild. A persisted completed historical brief remains readable; Q02 performs its own target/current-version authorization at send. No substituting a fresh route into an old job. Freeze the chosen attempt IDs and evidence pool at the editorial boundary through M04. Freeze source scope and source names via normal M04 behavior. Model generation identity uses F04/M01 profile generations; no user keys in job state.
3. One explicit advance owns at most one bounded source group or one other stage step. Claim in Store._write (BEGIN IMMEDIATE), compare the job stage, control flags and existing lease; issue fresh unique token for a due unclaimed/expired stage. Complete under a transaction checking same token, never trusting time alone. Each next stage releases the lease. Preserve success committed before lost stage acknowledgement. No async operation inside a SQL transaction. Competing workers may duplicate an unfinished public GET after lease expiry; stale workers cannot commit evidence/cache or make a new paid dispatch. A lease can expire while its old worker is waiting or performing I/O. Closing that worker's lease must never reset another worker's stage or infer provider non-execution.
4. Reuse RSS/Atom and GitHub/HF scope construction and existing fetches, including kind-specific grouping. Extract scope-building and one-group fetch entry points from FeedCollector/AICollector without changing setup preview/batch semantics. Collection manifest holds bounded planned scopes plus frozen unsupported-source gap IDs. Persist a collection reference and group index in existing feed_attempts.scope_json (indexed by these values). Scope-specific attempt is committed by EvidenceStore before fetch. Starting and finishing a Q01 attempt check the current job lease inside existing evidence transactions using an optional trusted per-collection guard; starting also checks pause/cancel and frozen route/profile. Ordinary preview/legacy calls use no guard. Retry an interrupted or cancelled free fetch using a new attempt; preserve completed outcomes (including failures and valid empty responses) for that group and never refetch after its completion solely because a later stage write failed. Mark replaced running attempts interrupted when reclaiming that group, preserving their audit identity. Finishing uses lease identity and the existing EvidenceStore scope checks. One source group per step bounds work and permits interleaving editions without extra worker infrastructure. The finished attempt supplies coverage and snapshot reference; no arbitrary evidence injection or raw cache mixing. Only currently supported public connector groups are executable, with other source kinds visible as gaps.
5. When no source group yielded a successful check (or retained usable partial evidence), end collection_failed with coverage, never call a model or generate a no-news brief. When at least one succeeded, hand the completed attempt IDs to M04 in stable order, including completed failures for coverage. A successful check with zero eligible items yields no_news and zero model I/O; report coverage gaps. A usable partial edition may proceed with coverage explicit. RSS/API statuses are existing fresh/stale/empty/no_eligible/not_modified plus source failure states. Treat API empty with reported incomplete coverage and no retained evidence as failure for the all-sources-failed decision.
6. Use stable job-derived editorial edition ID and M04's stable model task ID. M04 prepare is replayable for identical inputs, and M02 handles result/intent/retry/budget. Add one optional trusted before_dispatch hook to M02, forwarded through M04; invoke inside the same Store._write as the paid intent and budget reservation, after the asynchronous Keychain read. It checks lease, pause/cancel and original route/profile epochs. It never accepts data from a model or request, has no network and can refuse the dispatch without creating an attempt. Existing unhooked consumers behave identically. If a worker expires during a dispatched attempt, a successor may read status but M02 inflight/unknown/completed prevents another dispatch; it must not call global startup recovery while the old process might still be alive. At real startup the process lock is acquired first, then existing M02/Evidence recovery, then release abandoned job leases. Recover an inflight model attempt to outcome_unknown even if dispatched status is ambiguous. A storage error after dispatch leaves the intent and hold available for startup recovery. A subsequent job tick in the same process may display inflight/interrupted status, but cannot retry. Project unknown from M02 even if the job is paused/cancelled/stale or its editorial acknowledgement was lost. After explicit duplicate-charge acknowledgment, resume only the same non-cancelled job/task and only with valid current scope. A valid completed result can be applied after an interrupted editorial/job update without new charges. Backoff remains in M02 and is visible as waiting with next_at.
7. Persist media preparation as a separate stage. For text, store a text-ready plan referencing the edition; for a media style without an implemented capability, persist the text fallback and its reason. No fake image/success, no raw bytes. Advance the immutable handoff to awaiting_delivery only with a validated current ready edition and matching scope; no model replay if a media/queue write fails. no_news and collection_failed are terminal and produce no delivery handoff. Supply a read-only job projection (safe IDs, evidence/brief links, stage, lease status, failures, pause/cancel, budget/model status, media/fallback) and audit events with timestamps and bounded pagination. Stage transition and audit append share one transaction. Existing history remains unchanged.
8. Pause is durable; it stops future effects, permits the already-dispatched operation to settle and releases the worker at the next boundary. Cancellation is terminal for future work, records intent immediately, and cancels the active local coroutine when available; existing M02 converts dispatched cancellation to unknown. A worker in another connection observes cancellation through SQL guards and cannot launch any new operation. If a paid result was committed first, retain it as historical. Resume paused work explicitly; do not clear unknown by resuming pause. Check before effects, and before making a handoff; never replace old Bot/owner or partition for an existing job. Keep per-job in-memory task map only to expedite local cancellation, no global pipeline lock, no in-memory-only queue.
9. Make Pipeline the service entry point with create/get/list/advance/pause/resume/cancel/audit, available to Q03. ControlServer owns one instance, uses existing startup lock and exposes safe same-UID reads and pause/resume/cancel; no arbitrary paid job creation/advance via RPC in Q01. Tests use explicit in-process Pipeline creation and advancement. Close any active local workers before releasing control lock. Existing prototype start/legacy scheduler remains untouched.

## Tests and risk

- Same logical key idempotence, conflict and isolation across subscription/account/edition; two connections claim one current lease; expiry/reclaim rejects old token writes and new dispatch. Old worker after an awaited credential read cannot create an attempt. Second advance while old paid attempt is inflight issues zero requests.
- Restart between source finish and pipeline stage commit reuses completed sources, unfinished free reads repeat with distinct attempt records. Empty vs all failed vs partial, missing coverage, collection/edition/job trace. Scope/locale/profile epoch changes refuse effects. Confirm both RSS and API scopes retain current parser/cache behavior.
- Restore from DB with job stage before/after each write. Crash before intent, intent committed before dispatch, dispatch lost response, confirmed result before editorial acknowledgement, media/handoff commit failure. Observe requests and budget states, including zero fallback on unknown. Inject sqlite busy/denied writes and rollback; final result cannot appear as delivery-ready if storage fails.
- Pause and cancel one job during credential read/source/model stages while another continues. Persist status over restart. Cancel after paid dispatch preserves unknown. Read-only projection respects existing scope and never returns credentials, raw prompts or user secrets. Legacy upgrade creates zero new jobs and preserves last_slot/receipts. Later Q02/Q03/D integration tests will validate full runtime delivery.
