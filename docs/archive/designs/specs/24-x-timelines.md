# X02 / #24 — bounded official X timeline collection

## Acceptance and scope

Implement #24, R06 and IR-07 against independently approved X01 dcab041. One backend and the owner-configured X API credential. Fetch only approved public account and List timelines via api.x.com. Store attributed own text, canonical post URL and original/quote/reply/repost references with stable decimal IDs. Keep original/quote enabled by default, other types explicit. No scraping, alternative search, reference expansion, media, model or Telegram. Preserve incomplete coverage and prior complete cursor after cap, failure, crash, 429, overlap, unknown response or policy change.

## API and eligibility

- Use XClient safe GET and its known-versus-unknown response accounting. Official current OpenAPI excerpts retained from https://docs.x.com/x-api/users/get-posts and https://docs.x.com/x-api/lists/get-list-posts. For /2/users/{id}/tweets send max_results 5–100, optional since_id or initial start_time, a fixed end_time, and a validated pagination_token when continuing. For /2/lists/{id}/tweets send max_results 1–100 and pagination_token only, with post.fields in both. Request author_id, created_at, text, referenced_posts, possibly_sensitive and withheld; don't request expansions. Apply post type switches locally so accounting always counts returned rows. Parse IDs as canonical decimal strings and compare numerically using Python, never a signed SQLite cast. Require explicit timezone and creation time within the bounded window. Limit response size using existing transport and validated maximum rows, text/references lengths, duplicate detection and bounded token format. Never guess field names or auto-probe another dialect if denied.
- Account endpoint requires live XDirectory.binding, exact stable remote identity, approved current credential, enabled explicit X scope/partition and exact author match. List endpoint requires current complete authorized membership under this credential. A returned author must match an exact local+remote live member in its current classified partition and enabled X subscription, verified via the same X01 identity. Filter unclassified, out-of-partition, protected, missing/sensitive-in-ordinary and unknown-member rows before storing text. Type and author exclusions still count as observed/billed units. Unknown classification never gets an ordinary fallback. An explicit withheld row for a verified in-scope post leaves only a local non-displayable tombstone. A returned valid post ID from a verified ordinary in-scope author with possibly_sensitive true or missing atomically clears any previously cached ordinary body and writes the same conservative tombstone across that partition's account and List projections. A tombstone survives repeated or out-of-order earlier safe observations; it retains no body and may be pruned only once the post is beyond the supported cache window. Absence from a timeline never asserts deletion. Reject scoped identity mismatch or malformed page before publishing. Never store raw page or include unknown author payload in logs.
- For an active scan, freeze current config revision and exact credential ref, material scope/author mapping and List membership check stamp. Re-read after Keychain access, immediately inside the per-request intent transaction, and again at page commit. Any revision change conservatively stops an in-progress scan, even UI-only; any List snapshot operation changing its check stamp or authorization also stops it. Read cached immutable rows only through current X01 eligibility and exact same partition/local owner/remote author. A current ordinary claim must never see a row ingested under adult and vice versa. Cache survives unrelated UI changes for subsequent authorized reads. List results are additionally limited to current exact members and posts actually observed under that List; do not represent account-only results as List coverage.

## Durability, paging and cost

- Add a minimal X collector with SQLite tables for scans/checkpoints, per-step receipts and normalized posts plus scope observations. Cache text keyed by (partition, stable post ID), scope observations link account/List source, no duplicate body across overlapping sources in one partition. At most one unfinished scan per exact endpoint scope. Starting a manual scan freezes revision, type switches, page size (default 10) and initial 24h maximum backfill. Start has a caller-provided stable scan ID and exact-arguments idempotency. Each explicit step has a caller-provided stable step ID, reserves budget and makes at most one GET, then returns status. Repeating the exact step returns its durable projection and never sends a second request. Different operation arguments for a reused ID conflict. No interval worker in X02; X03 drives the same bounded interface.
- A scan holds its initial complete account cursor, upper time, floor and next opaque token. Bind completed account coverage to exact stable account/partition and the retained post type set. Reuse since_id plus fixed end_time only while requested types are a subset of that completed policy. After narrowing, a newly completed scan records its narrower set; a later expansion cannot assume the newly requested type was retained. Reject automatic expansion and require an explicit bounded fresh-window scan using start_time plus end_time, record the earlier historical coverage gap, and leave the prior cursor until the fresh window really completes. Initial scans also use start_time plus end_time. Don't silently reset an old complete cursor to hide a gap. A scan can be explicitly stopped/restarted with the same previous cursor, preserving the prior incomplete run and already-counted receipts. Empty validated final page completes the observed bounded request; empty with continuation, duplicate/non-progress, stuck token, malformed or nonmonotonic pages and bounded page cap never advance complete cursor. Account cursor is the highest valid received post ID even if its type is not retained, but only after uninterrupted validated coverage. Use numeric bounds and stable per-page first/last proofs. If no posts and no previous cursor, retain a latest successful window time without synthesizing an ID. Cap one scan to 12 pages; explicit safe resume uses the frozen durable token on known failure/limit until a bounded 30-minute checkpoint age. At cap or invalid/expired token, leave a coverage gap and require a new scan from prior completed cursor. No unknown retry through this interface.
- List scans freeze a local 24h floor and compare ordered observed UTC time/ID while paging; they never send since_id or server time bounds. Allow a resource-saving stop at the lower floor only after a monotonic observed prefix, but report bounded/incomplete coverage unless the API exhausted its token chain. Nonmonotonic input, repeated pages or changing membership cannot declare complete. Overlap is expected on later scans. Include bounds/reasons, no atomic List snapshot claim. Retain each scan's successful prior page results even when it later stops incomplete.
- Per actual GET, atomically persist unique in-flight step and reserve page_size local X read units before request. Reuse BudgetLedger's persisted X daily period (configured IANA zone, default Asia/Tokyo, historical period retained through timezone edit), independent of model costs. Shared total, partition and account limits apply in the same transaction. For Lists with any configured finite account limit, block before intent because unknown returned authors cannot be charged to account quotas safely; offer individual verified account requests. A known response settles at least one and any known returned rows, including duplicates/filtered; unknown keeps hold, no hidden retries. Confirmed 429 respects provider retry-after if available, otherwise an explicit conservative default and only a fresh step after backoff. Recover a persisted in-flight step to outcome_unknown at startup under the same exclusive lock. No fake actual invoice or tier claim.
- Commit known page accounting, checked normalized post/provenance, validated next checkpoint and cursor completion together in one Store transaction; crash before that commit leaves unknown, without advancing. Explicit live config mismatch may settle known usage without writing posts/checkpoint, expose safe incomplete state. Older scans cannot revive an authoritative withheld tombstone. Local projection caps rows and excludes aged-out body from read scope; an explicit scoped purge can remove cached bodies without changing receipt, cursor, status or dedup semantics. O01 can reuse that safe boundary later. Use existing private same-user control, startup recovery and no new daemon.
