# Q03 / #29 — durable wall-clock schedule and bounded recovery

## Frozen contract

Every enabled subscription and configured special account can have several stable local times and an IANA time zone. Start preparation before the target send time. Keep ready work until the target; if preparation misses the target, record late and send only during the configured catch-up window. Default to the newest eligible missed occurrence per scope and a six-hour catch-up window. Record expired existing occurrences as skipped and do not silently replay old receipts. DST gap times advance to the first valid local minute, overlapping times run once. Time and zone changes do not resend completed logical occurrences. Before dispatch recheck deadline and current preparation/delivery authority. If content or explicit assignment changes before any delivery intent, safely re-evaluate or rebuild. If a delivery is already confirmed or may have left, keep receipts and stop affected remaining parts with an actionable partial status. A single unavailable Bot does not hold up its authorized peers.

One existing local backend with a bounded async tick, one owner and several Bots. Q01 handles durable preparation and paid unknown holds. Q02 handles durable send intent/ack and exact target binding. S05/X03/D01/D02 later add their collectors/assets. Current mockup retained. No deployment, historical send activation, per-Bot daemon or cloud wake-up. The legacy prototype scheduler remains compatible.

## Persistent state and authority

- Add schema 14 using existing migration. One schedule policy row with revision/CAS, enabled, catchup_minutes 0–1440 (default 360), preparation_lead_minutes 1–120 (default 15), and explicit optional model hold per normal/adult partition in microdollars. Keep automated scheduling disabled on upgrade and require an explicit local enable; record activation time. Unconfigured model hold surfaces a blocked reason and prevents paid preparation. Use current F02 primary/backup profile IDs to construct Q01 hold policy; let M03/M02 check price, caps and actual attempt accounting. No guessed bill amount or automatic price lookup.
- One scope row per subscription or actual priority-special account, with stable slot IDs mapped to local times and zone, plus cutover and last tick. Reconcile times by exact match first, then pair remaining old and new times in deterministic time order to retain identity through moves, allocate IDs for added slots, retain removed identities as tombstones for exact-time re-add. Updating zone preserves slot IDs. Re-enable or time/zone/identity change sets a cutover so old newly interpreted elapsed slots are not backfilled. The completed occurrence key is (scope, stable slot ID, local calendar date); the DST fold and UTC offset are not part of identity. Completed/skipped keys stay closed under later configuration. Same day retiming of a completed slot does not re-run it.
- An occurrence row records the logical key, resolved target UTC, preparation boundary, send cutoff, current generation, Q01 job ID, status/reason and timestamps. Unique key and CAS prevent two ticks from creating different runnable versions for the same occurrence. Phase scheduling and evidence remain in Q01/Q02. First claim occurrence, then create Q01 job with deterministic key derived from occurrence/generation, then attach; a crash between commits reuses that job key. New generation retains prior jobs. No outer transaction spans Q01/Q02 transactions or awaits. Preserve legacy last_slot and receipts as historical data.
- Resolve local times by round trip through ZoneInfo and UTC. For fold, use earliest distinct valid UTC instant. For gap, find first valid minute at or after configured minute; bound search to one civil day and skip an entirely missing date visibly. Use aware UTC throughout cutoff/lease math. Revalidate deterministic logic with Tokyo and Sydney plus cross-midnight cases. Past timezone data depends on host IANA zoneinfo; no fixed DST offsets.
- Enumerate bounded near-term occurrences using configured scope/times. During normal cadence, plan each occurrence within lead time. After restart or a tick gap over 90 seconds, prepare/send only the newest eligible elapsed occurrence per scope, while future lead-time occurrences remain independent. Mark older elapsed in-window occurrences superseded and persisted expired occurrences skipped; record a bounded recent history for missed expired slots, never loop back years after long sleep. Startup recovery preserves unresolved sends and paid intents, including on superseded occurrences. Start cold activation from cutover, so existing late schedules are not fired just by upgrading. No delivery before target; mark late at target if preparation incomplete. Continue until target plus catchup (current minute allowed for zero). Do not erase a pending unknown if deadline expires.
- One async scheduler task owned by ControlServer and capped local phase workers. No new server or per-Bot process. Check policy on each tick, derive ready work and interleave by scope with a small fixed concurrency. Pipeline and Outbox leases/atomic claims remain effects authority. Pass one optional trusted schedule guard to Q01/Q02 work, invoked in the same transaction that would begin a source attempt, paid model intent or Telegram send. Re-read enabled policy, active occurrence/generation, fresh UTC deadline, partial/uncertain recipient-edit hold and current binding before an intent, including after awaited credential/asset reads. This guard does not control result settlement. Its false return commits any occurrence hold/status without creating an intent; do not throw from inside a transaction after saving the hold. A caller can unwind after the transaction returns. Adapt the existing EvidenceStore.begin and ModelRunner.check_work callers that currently discard hook results. Only explicit False refuses; None preserves all existing hook behavior. Source begin returns no attempt after committing refusal, and both RSS and API callers unwind without opening a request. ModelRunner returns pending status after committing refusal instead of reserving or dispatching; do not alter existing dispatched result settlement. Verify zero source/paid intent and durable scheduler hold under False. Q01 collection/paid hooks preserve current behavior for other callers; Q02 checks after its own eligibility and before _begin. Snapshot the assignment set at the first accepted send guard in the same transaction as the intent. Deadline or policy-denied guards must not rely on the next tick or on local task cancellation. Production uses fresh UTC; tests pass clock explicitly. Cancel local workers on service stop using existing conservative unknown semantics. Do not activate the developer's installed runtime.
- Work through Q01 preparing steps and enqueue Q02 only for ready edition at/after target. Confirmed results get reused. Stage read errors/blockers and no_news/collection_failed are distinct. Current runner supports configured RSS/Atom/GitHub/HF groups; unsupported X/source work remains visibly blocked until its dependency lands, with no fallback collection. Profile readiness/budget holds/route blockers stay explicit. On catch-up cutoff no further effects; already-issued attempts may finish and their receipts remain.
- Content changes (partition, locale, selected evidence/model/edition config) before any Telegram intent require superseding the unsent version if its paid state is known. Explicit target changes before send use Q02 recipient reconciliation and reuse ready content. While Q01 preparation is stale, rebuild only if previous paid result is confirmed or definitely unstarted, never when an attempt remains inflight/unknown. No automatic duplicate charge on the same occurrence. On any existing Telegram intent, content change blocks all pending parts; preserve historical successes/unknowns. After partial/uncertain delivery, explicit assignment edits (addition or removal of a still-valid configured Bot) pause remaining work and ask the owner to choose. Pause/unbind/delete/opt-out of a particular Bot stays scoped to that Bot, and its peers continue when their route is unchanged. No automatic addition after first intent. Persist partial configuration status before advancing more parts. Local user can stop remaining parts, or explicitly continue only unchanged original bindings after a target-only change; changed-language/partition content never resumes in that old edition. Next eligible occurrence uses current configuration.
- Same-UID RPC for read/update policy, bounded schedule status/recent occurrences and explicit partial action. No scheduler-created messages from RPC handlers; normal backend worker effects only after explicit enable. Existing config editor sets actual times/timezones. Report target-at, prepare-at, late/skipped/superseded/blocked/no-news/partial states with safe IDs and evidence links. No credentials or raw contents.
