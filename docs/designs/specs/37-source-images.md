# D01 / #37 — validated publisher-supplied pictures

## Frozen contract

Existing effective style precedence and approved mockup. Default is text plus original links, with Telegram link preview disabled. Only the ordinary route's explicit source_image style can download a publisher-supplied image. Attach at most two image parts after the qualifying text. Source images carry the related evidence/article, publisher URL and verifiable photo credit when present; never imply a generated image is a scene photo. Adult ordinary delivery is text with previews disabled, including if an inherited image style was requested. X04 owns explicit adult X media, D02 newspaper generation. No replacement image searches, paid generation, new runtime or new configuration mode. Any missing, restricted, expired, oversized, invalid or unavailable asset yields a safe recorded fallback and keeps qualified text/citations.

## Design

- Use Q01's prepared current edition and exact M04 selected evidence anchor. Add one read-only EditorialService helper reconstructing anchor from validated result item's event_key and its frozen cited pool (existing hash of partition and anchor URL). Return only unique matches, in output order. Read the current same-partition EvidenceStore article snapshots associated with that job and subscription; match canonical article URL, content hash, explicit publication and fetched time to the frozen anchor. Do not derive candidate from model text, related reprints, arbitrary caption URL or separate search. At most two matching image candidates, one per selected event, with no fallback fetch of other articles on failure. Keep Article.image_url as existing parsed publisher evidence; append optional image_credit (default empty, outside content hash, old serialized snapshots continue to decode). Feedparser may flatten credits, as verified with a synthetic media:content/media:credit fixture. Only retain a unique explicit media:credit associated with the sole matching media:content image, and show credit unavailable when attribution is absent/ambiguous. Preserve original publisher and canonical link independently.
- Use F03 source transport, GET only, bounded response (5 MiB input, 15 seconds each, 40 seconds total for preparation), exact public HTTPS URL without userinfo or sensitive token/credential query, DNS and actual endpoint guard. Send no credential/cookie/referrer; do not join publisher sessions. Redirects at most two and same approved origin with the same URL validation; no JS, alt media discovery, site-wide permission guess or raw URL upload. Accept JPEG, PNG, WebP only when declared type and decoded format agree. Use current maintained Pillow CPython wheels via one locked dependency (Python 3.12+); explicit formats, no multi-frame/animated input, dimensions/pixels checked before pixel load, decode/verify and re-encode normalized JPEG bounded to 2 MiB and max edge 1920. Strip all EXIF/ICC metadata and discard original bytes. Absolute guard catches decompression/format/corrupt data and Telegram aspect/size constraints. Apply EXIF orientation locally, composite alpha onto a neutral background. Unusable image never modifies text. Keep only approved final bytes and safe reason, no raw response or credential logging.
- Store assets in an owner-only media directory beneath existing backend data directory, with normal source-only opaque IDs source_<sha256>; all IDs and filename generated internally, read via the same directory FD with owner/mode/regular-file/O_NOFOLLOW/size/SHA checks. Write private temp files, fsync and atomic rename before publishing manifest references. Existing local bytes can be reused; small orphan files after a crash are harmless and O01 owns retention of unreferenced history. Never delete an asset referenced by pending/unknown receipt, no raw originals or extra database. Do not put absolute paths in the RPC or DB. Outbox validates source-prefixed assets only for ordinary route, and unchanged Q02 hash and MIME checks before actual multipart; one byte file reused across multiple Bots. A confirmed or uncertain text part never repeats because a photo fails. Asset provenance belongs in Q01 media result; Q02 photo descriptor remains its existing exact typed shape and includes localized caption naming article publisher, original link and explicit credit or unavailable label. If caption cannot retain complete URL in 1024 UTF-16 code units, keep text only for that image.
- Add one optional SourceImages producer to Pipeline and wire production only in the existing ControlServer. Guard exact job lease, route and prepared edition before each public image request, after awaiting fetch/decode, and before publishing descriptors. Suppress stale photo data, preserve any existing frozen job/Q02 receipts. For the integration on a reviewed Q03 base, compose the schedule effect guard inside the existing write transaction before every image GET, consuming explicit False without publishing or transitioning past preparation. Do not rely on timers or worker cancellation. Q02 alone has only its local lease guard, so current branch may build against that predecessor; reverify Q03 composition before actual merge. Results are durable Q01 payload; Q02 loads the already checked file and reuses per-Bot receipts. If no producer or incompatible style, existing text behavior remains. No schema version change needed for additive Article field, private file storage or new payload fields.
