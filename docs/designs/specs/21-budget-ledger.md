# M03 / #21 — Durable spending and X read reservations

## Frozen contract
One local SQLite ledger, no billing service, payment credentials, automatic top-up or external account lookup. Model currency total, image subset and per-provider limits share reservations across task attempts (primary/backup/repair); X read-count total/partition/account limits are a separate meter. Reserve before dispatch, settle confirmed costs, release only definitely unsent attempts, retain unknown spending across crashes. One attempt identity reused for multiple delivery Bots cannot charge twice. OpenAI user-reported100USD credit is informational, applies only to its bound organization and does not become an X/other-provider balance or an automatic spending limit.

Acceptance: atomic concurrent admission under all applicable caps; durable attempts and periods; distinguish maximum reservation, usage-derived/reported cost and unknown usage; unknown outcome retains hold; updates never retroactively rewrite past price snapshots. No invented current prices or verified billing amount. Out-of-scope: actual model/X dispatch, SDK fallback executor, remote billing reconciliation, UI views (later consume ledger report).

## API and storage
Add BudgetLedger over same Store connection and existing _write transaction. Database schema4 adds budget_policy singleton(revision,document), budget_periods(id,meter,start,end,timezone,cycle_day), budget_attempts(unique_id,task_id,meter,partition,provider,account_id,image,period_id,reserved_units,settled_units,state,quote_json,usage_json,created_at), budget_tasks(meter,task_id,limit_units). No ORM, external queue or generic rule engine.

Policy is a small strictly validated JSON document with model monthly micro-USD total/image/provider caps, X daily total/partition/account read caps, model timezone+cycle day1..28, separate X timezone, price table keyed explicit provider/model entries and optional openai-credit annotation. All limits initially null/unlimited, prices empty, user-reported100USD annotation explicitly unverified/unbound and never subtracted from counters. `budget.get/save` on private existing control interface exposes policy revision CAS; policy independent from news routing (every reservation reads active policy inside same transaction). Same backend sole writer. Lowering a cap below existing usage succeeds but blocks further admissions; does not erase existing holds or call providers.

Money is integer micro-USD, never binary floats; X units are integer reads, never dollars. reserve(attempt_id, task_id, meter, partition, provider, account_id, image, max_units, quote, task_limit=None, now=awareUTC) atomically admits current period + all relevant caps and freezes quote (rate_version/model/source/known-or-unpriced). `max_units` is a required conservative bound from caller; unknown price requires an explicit positive hold and is marked unpriced. Zero hold only for known zero-price quote. No token-count guessing in this module. Price table updates affect future quotes only; quote helper calculates ceiling from explicitly configured integer token rates and token maxima, never ships guessed provider prices. Unknown quote cannot authorize an unbounded call: M02/X02 must supply bounded request parameters or block pricing_unknown before dispatch.

attempt_id is stable across same paid operation, excludes target Bot. Same ID + identical frozen parameters returns existing record without a second reservation; changed arguments reject idempotency_conflict. Task cap is frozen first time per meter/task_id; a later higher/different cap rejects, so backup/repair cannot reset it. Model task spend sums across providers/partitions, image also counts toward total. X scopes total/partition/account apply simultaneously. Meter/task identities are separate, so read counts never mix with dollars. No cross-partition content reuse is introduced by an aggregate budget.

States reserved → inflight → settled or outcome_unknown; reserved → released only when definitely not dispatched. `begin_attempt(now=awareUTC)` persists inflight before caller may send; only reserved may transition, repeat inflight/settled cannot authorize another dispatch. Refuse reservation_expired if now is outside its frozen period (including before its start); a never-dispatched expired reservation can be explicitly released and replaced by a fresh attempt in the current period. This prevents old-period holds from admitting new-period dispatch beyond the new cap. `recover_inflight` changes all inflight to outcome_unknown on sole-backend startup, retaining holds; reserved remains reserved until caller explicitly releases it. `settle` accepts actual/usage-derived units or None only from inflight (or repeats identical settled result). None records state=settled with settled_units=NULL, retaining the full hold as cost_unknown; a known response with unknown cost is distinct from outcome_unknown and must not be auto-reissued. Known settlement charges the reported amount even if above reservation (overrun visible, future admission blocked), never clips evidence. Idempotent equal settlement is no-op; conflicting settlement rejects. Reserved cannot settle before begin_attempt. An inflight/unknown attempt cannot simply release; explicit `reconcile` supplies confirmed result or definitely-unsent evidence, with a nonsecret reason, and preserves original quote/record. This module does not grant automatic retry or result-query capability.

Report shows per-meter/period reserved, known settled, unpriced/unknown retained, overruns, source of figures, remaining configured limits; not an official bill. Store only bounded numeric usage fields and safe identifiers, no prompts, keys, URLs or raw provider errors. Reports describe OpenAI credit solely as user declaration with optional bound-org/expiry metadata, unverified unless later explicitly supplied evidence; no automatic official balance claims.

## Period boundary / IR-07
Persist actual UTC start/end for each model-month and X-day period, plus the timezone/cycle parameters that created it. A policy timezone/cycle edit never changes an already-open period or its consumed/held amounts: new parameters take effect after its original end. On first reservation after expiry, choose current calendar interval under new policy with start=max(previous_end,calendar_start(now)); no overlap/double budget for the same UTC instant. Gaps have no calls and need no empty rows. Use aware UTC times, IANA ZoneInfo, local calendar boundaries (DST day may23/25hours). Model billing cycle day constrained1..28 avoids month-end ambiguity. Model and X periods independent, default Asia/Tokyo with month day1. Attempts stay charged to their original persisted period even if settlement happens later; unresolved old holds remain visible, never silently released by rollover. New period has its own cap; task cap remains across rollover. Reject caller clocks before latest stored period start instead of rewriting history.

Unknown price/usage/timeout retained; known overrun recorded and next call blocked; release only reserved; repeated/conflicting settle. Month rollover, billing cycle, DST, timezone edit midperiod doesn't reset usage, X vs model separate keys, late settlement oldperiod, reserve-before-boundary/begin-after-boundary refused with no dispatch authorization, task cap acrossperiod. Price update oldquote immutable; report never treats usercredit as actualbalance or pays nonOpenAI spend. Policy CAS and malformed/negative/float units reject. No extra framework or event bus.
