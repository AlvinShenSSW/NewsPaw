# 模型主备与语言配置

状态：用户确认的目标设计，尚未接入运行中的 App 或后台。API 标识依据 2026-11-07 官方资料核对，未调用真实账户或付费模型。

## 默认主备

| 配置组 | 角色 | 显示名称 | API 模型 ID | 默认 API Base URL |
| --- | --- | --- | --- | --- |
| 普通 | 主用 | OpenAI GPT-6 Luna | `gpt-6-luna` | `https://api.openai.com/v1` |
| 普通 | 备用 | MiMo Flash | `mimo-v2.6-flash` | `https://api.xiaomimimo.com/v1` |
| 成人 | 主用 | DeepSeek Flash | `deepseek-flash` | `https://api.deepseek.com` |
| 成人 | 备用 | Grok 4.3 | `grok-4.3` | `https://api.x.ai/v1` |

四个槽位都可单独编辑 URL、API Key、模型 ID，不把别名猜测或型号升级静默写入配置。接口显示名与实际 API 模型 ID 分别保存。

世界、日本、澳洲、中国、数码电子、AI 动态与普通 X 继承普通组；AV 产业与 X 成人博主继承成人组。每个分类可选择“继承默认”或“独立配置本分类的主备”。继承关系在界面明确显示；编辑独立覆盖不修改全局组，也不改变内容分区。

## 每个槽位保存什么

基本设置：

- 提供商/适配器、显示名称。
- API Base URL、模型 ID。
- API Key：实际秘密放 Keychain，配置只保存引用；主备各自绑定，不把一家的密钥发送给另一家。
- 已配置/未配置、最近连接验证结果与验证时间。

高级设置：请求协议、超时、最大输出、重试次数、任务能力、预算。普通用户不需要为官方默认手动选择协议；自定义 URL 的协议与模型能力由连接测试确认。

Base URL 不是完整的单次请求路径。适配器负责拼接对应 endpoint，避免重复添加 `/v1`。保留 URL 可编辑能力，但不把任意“OpenAI compatible”接口视为完全兼容。更改 URL、模型或密钥后，旧的连接验证状态失效。

界面中的模型 ID 是可编辑文本，不能只有写死的下拉框；可以显示从该接口查询到的可用模型作为辅助，但不能假定每家供应商都有同样的模型列表接口。

## 主备切换规则

任务在开始时冻结内容分区、证据快照、目标语言、模型配置版本和预算。先调用主用；确定未发送或收到适配器认定可安全重试的失败响应时，有限重试后可使用同组备用。超时不自动等于未执行。记录每次尝试的提供商、模型、状态、耗时与实际返回的用量，不记录 Key 或媒体原文。

每次收费调用派发前，须先持久化唯一 attempt 的执行中记录并原子关联费用预留；落库失败不得派发。恢复时，对无持久化确认结果的执行中 attempt，一律先转为 `outcome_unknown`，不能仅因 lease 过期判定未执行；即使实际崩溃发生在持久化后、派发前也保守等待。请求可能已执行而响应丢失、或结果落库前进程退出时，进入持久化 `outcome_unknown` 并保留费用预留。只有该供应商经过验证的幂等或结果查询能力能支持自动恢复；否则不自动重复请求或切换备用，需用户明确承担可能再次收费的重试。已持久化确认成功的结果直接复用，不承诺供应商侧严格恰好一次。这同样约束生图等收费调用；明确返回但格式错误的结果仍可在预算内进行已定义的修复。

- 遵守服务返回的重试时间，主备尝试均计入同一个任务预算；备用没有可用额度时不绕过总预算继续调用。
- 主用长期故障进入冷却期，避免每份简报都重复等待相同失败；后续任务可在规定的健康探测后恢复主用。
- 401、无权限、模型不存在、参数不兼容等配置问题明确标注；不反复重试相同配置。若已验证的备用可用，可以在故障状态可见的前提下接管，不能显示“主用正常”。
- 余额耗尽、平台限额与本机预算不同，分别记录；不得通过备用绕过用户设定的总费用上限。
- 来源 RSS 无内容、X 数据缺失或 Telegram 发送失败不是模型故障，不因此重复调用另一家模型。
- 结构化结果不完整时，只允许有界的格式修复或同组备用，重新校验引用与时间，不把空响应当成成功。
- 内容审核拒绝属于独立状态，不作为自动切换供应商以绕过限制的触发条件。成人组处理非露骨行业资讯和账号动态摘要。
- 主备均不可用则保留任务并显示原因；不跨普通/成人组尝试，不原样转发未整理的源内容。

切换复用同一份证据，不重新抓取 X 或 RSS。每次模型请求使用本轮有限上下文，不把另一提供商的整个对话历史盲目转交。新闻发送使用已校验的冻结正文，投递重试不会再次花费模型调用。

## 协议与多模态能力

四个提供商目前都有 Responses 文档，但参数并不完全一致。OpenAI、DeepSeek、Grok 和 MiMo 需要各自的适配器，不能只替换 URL。

尤其 MiMo 文档的 Responses 工具选择仅支持 `auto`，不能依赖强制指定某个函数；文档列出的输出格式也不能据此保证兼容 OpenAI 的严格 `json_schema`。MiMo 适配器必须限制可用工具、对实际工具调用与 JSON 做本地校验，并对无工具调用、额外参数、来源编号异常作出明确处理。

文本、图像理解、图像生成、音频转写、语音生成是独立能力。主备的模型名不表示所有能力都相同。执行前检查当前任务要求；备用不支持图片或语音时，不能盲发媒体或悄悄忽略图片。允许的降级必须明确，例如已取得可信转写后只做文本整理；否则等待对应能力恢复。

AI 报纸另设普通/成人的生图主备槽位，每个槽位同样有独立 URL、Key 引用、模型 ID 和能力验证。普通生图主用按 OpenAI 图像 API 方向设计；具体生图型号及备用尚未选定，均保持未配置。成人生图与视觉校验不跨到普通组。这里的四个默认文字模型不自动继承为生图模型，也不因为支持图片输入就显示“可以生成报纸”。报纸文字先由对应文字组完成，再由对应生图组生成并校验；详见 [推送样式](delivery-formats.md)。

MiMo 的 Token Plan Key（`tp-` 开头）只在订阅页显示的 Token Plan 地址上有效（如 `https://token-plan-cn.xiaomimimo.com/v1`，另有 `sgp`、`ams` 区域），在按量付费的 `https://api.xiaomimimo.com/v1` 上会得到 401。适配器遇到这种组合不发请求，返回 `token_plan_endpoint`，界面提示到「自定义 API 地址」改地址。

当前已有适配器的强制工具调用和结构化输出实现不能直接用于 MiMo。现有代码中的旧默认模型是原型参数，尚未按本表迁移；生产接入需要相应实现与联调。

## 两种独立语言

| 设置 | 值 | 控制范围 |
| --- | --- | --- |
| `ui_locale` | `zh-Hans` / `en` / `ja` | App 菜单、页面、按钮、状态与错误提示 |
| `news_output_locale` | `zh-Hans` / `en` / `ja` | 所有分类和 X 简报的最终标题、摘要、说明、报纸图片文案与播报语言 |

默认均为 `zh-Hans`。UI 中分别显示“App 显示语言”和“默认新闻输出语言”，可任意组合。用户输入的账号、源名称、模型 ID 和 URL 不由 UI 翻译器改写。

采集保留原文与来源语言。模型按目标输出语言生成最终简报，遵循相同事实与引用约束；不能为了翻译补造背景或改变数字。英文界面并不要求抓英文新闻，也不要求输出英文。

翻译任务遵守原内容分区：成人原文仍由成人主备处理，不能先交给普通组翻译。备用接管时沿用同一个 `news_output_locale`。

摘要缓存键包含输出语言、证据版本、分区、提示词版本与实际模型。切换界面语言只更新界面；切换新闻输出语言影响未来及尚未发送的简报，不重发历史消息。未经翻译的原文可在证据查看中保留，不能冒充目标语言的最终简报。

## 验收重点

1. 四个槽位都能保存各自的 URL/Key 引用/模型；密钥不出现在导出、日志或主备切换记录。
2. 分类继承与覆盖可追踪，修改一个分类不改变其他分类的配置。
3. 模拟确定未发送或已收到可安全重试失败响应，同组备用收到相同证据和目标语言，且不额外抓取 X；普通/成人不会交叉调用。另测请求已派发后的未知超时，以及派发后、结果落库前进程崩溃：重启恢复为 `outcome_unknown`、保留费用预留，无经验证的幂等/结果查询能力时零自动二次调用（包括备用）；派发前记录落库失败则零网络调用。
4. 主用配置错误、审核拒绝、预算耗尽、来源为空、消息发送失败被区分，不形成无界重试。
5. 切换界面到 English、输出到日本語，所有最终简报使用日文；反向组合与中文也可用，时间和订阅保持原值。
6. 源标题、数字、发布时间、URL 与人物归因在翻译后仍可回溯；输出失败不会直接推送未翻译原文。
7. 文字主备和生图主备互不覆盖；未配置图像能力时不能错误调用文字 endpoint 生成图片。改新闻输出语言后，待发送报纸须重新制作或降级为新语言文字。
