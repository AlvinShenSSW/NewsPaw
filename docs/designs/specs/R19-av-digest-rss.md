# R19 — 0.6.4：AV 产业简报采用 RSS 来源，由模型写概览与摘要

来源：所有者 2026-11-10 的指令。没有 GitHub issue。所有者的原话：

- 「我让 av 产业试着发了一期但并没有收到」
- 「需要改代码允许 rss」
- 「这是之前 openclaw 给我做的新闻，首先第一段是对全天新闻的总结，然后是具体新闻」（附一期样例：标题行、「今日概览」一段、逐条的标题 + 两三句摘要 + 来源 + 链接；样例里的条目同时来自 RSS 源和 AV研究所，全部是模型写的正文。）

这一条覆盖 `18-av-industry.md`「Editorial and delivery」里的两点：AV 简报只采用 AV研究所 的结构化条目；可发布的标题 / 正文必须等于固定模板。其余内容（采集、分区、投递守卫）不变。

## 现状（已读代码与本机数据）

- `EditorialService._pool`：分类为 `av` 时只保留 `evidence_scope == "av_industry_excerpt"`、来源与链接都在 fiu758.com、且能套上 `industry_copy` 模板的条目。所有者挂在 AV 分类下的两个成人 RSS 源（2chav.com、avno1tw.com）读取成功（10 条、4 条），进入选稿的是 0 条，任务以 `no_news` 结束，不发任何消息。
- `BriefValidator(av_industry=True)`：标题 / 正文必须逐字等于模板，不允许分歧说明、实体。`_submit` 把模板作为 `allowed_copy` 交给模型。
- 语言检查：`zh-Hans` 的输出里不允许出现假名和常见繁体字（只豁免本地词表里的名字）。日文人名、厂牌名、作品名没有汉字写法，照现在的规则任何保留原名的中文摘要都会被整份拒绝。
- `render` 没有概览段。成人分区不取来源图片（`source_images.py` 只处理普通分区）。
- 用固定模板套现有两个 RSS 的 20 条：avno1tw 0 条命中；2chav 10 条全部命中同一句「发行公告」（来自每条相同的套话）。固定模板对 RSS 没有信息量，所以所有者选择由模型写正文。

## 冻结的验收标准

V1 选稿
- AV 分类的简报采用它名下所有成人来源的条目：RSS / Atom 与 AV研究所 同等进入候选，不再要求来源域名或模板命中。仍只在成人分区内取证据；非 AV 分类仍排除 fiu758.com 的条目（不变）。
- 只挂 RSS 源、有新鲜条目的 AV 简报不再以「无新闻」结束。

V2 正文
- AV 简报的标题与正文由成人分区的模型按普通简报的规则书写（逐条引用原文片段、数字必须出现在引用里、不得声称独立核实、输出语言检查、同一事件不重复），不再要求等于固定模板；允许分歧说明。
- 人名、厂牌、作品名可以保留原文：模型把保留原样的名字列为实体，`source` 与 `translated` 相同且逐字出现在证据里；这些名字不参与输出语言检查。仅 AV 简报如此，其他简报的语言检查不变。
- 仍只用成人主 / 备模型，不回退到普通模型；模型拒绝、失败、结果未知的处理不变。

V3 概览
- AV 简报的模型输出增加 `overview`：有条目时必填，一段话概括本期最值得关注的动态，上限 600 字符；没有条目时必须为空。概览与正文接受同样的检查（数字须出现在本期被引用的原文片段中、不得声称独立核实、语言检查并同样豁免保留的原名）。
- 发出的文字以「今日概览」（English「Today at a glance」/ 日本語「本日の概要」）加概览段开头，随后是原有的逐条格式（标题、正文、来源、时间、链接）。其他简报的输出不变。

V4 投递守卫
- AV 简报结果的标记改为新版本；投递前仍要求结果带有已知的 AV 标记（新版本或旧的 `industry-v1`），没有标记的旧结果仍被拒绝。

V5 发版
- 版本 0.6.3 → 0.6.4，build 10（同 R16 D1 的五个文件）；合并后从 main 打包，DMG 放到 `~/Desktop`；ad-hoc 签名，不声称公证。

## 不变量

- 普通 / 成人分区不跨组：AV 证据只交给成人模型，只发给允许成人内容的 Bot；fiu758.com 的条目不进入其他分类。
- 不新增自动付费调用、不新增图片或媒体；成人简报仍不带来源图片、不朗读。
- 模型无权执行 shell、修改订阅或目标；来源文字作为不可信资料交给模型。
- 离线测试不产生外部调用。

## 非目标

- 不做样例里的「每日AV前线｜日期」标题行与逐条「关键信息」行（所有者只明确要求了概览段与逐条新闻）。
- 不抓取 RSS 条目的正文页：摘要只依据 RSS 给出的标题与摘录，篇幅会比样例短。
- 不改 AV研究所 的采集（仍只收有行业事实线索的条目）、不改来源管理界面、不做「无新闻」时的通知。
- 不改其他分类简报的选稿、校验与输出。

## 假设（未验证）

- 成人主模型（DeepSeek）会按要求输出概览并把保留的原名列为实体；不合格的输出按现有规则重试一次修复，仍不合格则该期不发。未用真实模型验证。
- 2chav 每条摘录是相同的套话，模型实际只能依据标题写。

## 做法

- `editorial.py`：`_pool` 的 AV 分支只保留分区判断；`BriefValidator` 的 AV 开关改为「概览 + 保留原名」；`_submit` 换 AV 指令并去掉 `allowed_copy`；`_decorate` 写入 `overview` 与新标记；`render` 在开头输出概览。
- `av_rules.py`：删除不再使用的 `industry_copy` 与模板表；`industry_fact` 仍由采集使用。标记常量改为新值并保留旧值的集合。
- 不改数据库结构。升级瞬间仍在处理中的旧 AV 期次会因候选变化被判为过期，由下一期接替（接受）。

## 测试计划

- Python：只有 RSS 源的 AV 简报经整条流水线到达待投递，文字含概览、模型摘要与原文链接；RSS 与 AV研究所 条目同时入选；非 AV 成人分类仍排除 fiu758.com；校验器接受有依据的自由摘要、在 `zh-Hans` 下接受声明为实体的假名原名、拒绝未声明的假名、拒绝缺失 / 多余 / 数字无依据的概览；非 AV 校验器拒绝 `overview` 字段且语言检查不变；旧 `industry-v1` 标记可投递、无标记拒绝；`render` 的三语概览标题。
- 全量：`uv run pytest -q`、`uv run ruff check .`；Swift 无改动，仍跑一次 `swift test`（`macos/NewsPaw`）确认版本号改动不破坏。
