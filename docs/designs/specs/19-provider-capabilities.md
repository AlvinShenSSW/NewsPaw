# M01 / #19 — four provider protocols and capability verification

## Spec review / frozen contract
Provide the four configured text providers as explicit adapters and persist capability-specific connection results. Preserve default exact IDs gpt-6-luna, mimo-v2.6-flash, deepseek-flash, grok-4.3 and each independent URL/Keychain reference. Saving/configuring performs zero network or paid calls. An explicit probe reports the tested profile/capability, authentication/model permission/protocol errors and observed usage; it cannot imply other capabilities work. URL/provider/model/key/partition changes revoke prior validation, including change-away-then-back. No silent model upgrade or cross-partition fallback.

Scope: provider wire request/response normalization, bounded text/vision/tool requests, effective capability records and explicit bounded connection probe API. Image/STT/TTS records exist independently and remain untested or probe_unavailable until their assigned D02/D03 adapters exist; text or image-input support must never mark image-generation/audio successful. M01 does not claim those media operations implemented. M02 owns general durable task execution/retry/fallback/cooldown. M04 owns editorial output and citations. No Telegram, source fetch, UI redesign or automatic model-list discovery.

## Design and acceptance
Use one small providers.py with a fixed provider→protocol policy map/functions, not a plugin/class hierarchy. All four use Responses but each builds only supported fields. F03 provider_client enforces exact trusted origin, maxresponse2MiB/deadline90s and zero retries; explicit base URL normalized by stripping trailing slash then appending /responses exactly once (never inject /v1, reject a full operation URL). Unknown provider fails before credential read/network.

A bounded immutable request describes trusted instructions, untrusted text, optional inline validated PNG/JPEG/WebP image, maximum output tokens1..32768, optional one named function with caller-supplied JSON schema/required-result validator. No raw arbitrary API kwargs, hosted tools, remote media URLs or conversation IDs; no model-controlled shell/tools. Size limits reuse existing10MiBimage and bounded text/context. Adapter checks matching declared content partition/profile before dispatch. MiMo uses tool_choice auto and strictfalse; other providers select the single namedfunction. Every returned tool call is locally checked for exact name, onecall, parseable object, no unrequested keys, and supplied domain validator; no schema-trust-only path. Plain/JSON text checked for expected shape by caller; malformed/incomplete/empty/refusal are distinct and never auto-retried. Tools are returned as data, never executed by adapter. All SDK/provider response reasoning is discarded, not stored/logged or forwarded.

Normalize response: safe response ID/model ID, output_text or validated tool arguments, numeric token usage allowlist, response status. Record requested versus reported model separately; a differing reportedmodel is visible, no config rewrite. Error codes distinguish credential missing/locked, 401 authentication,403permission,404model unavailable,400parameter/protocol,429rate/quota (safeallowlistcode),5xxprovider failure, policyrefusal,invalid/incompleteoutput, transport connection failure vs outcomeunknown. Raw provider errors/headers/keys never enter diagnostics. No automatic fallback on policy refusal or unknown dispatched outcome.

Database schema6 adds profile_epochs(profile_id,generation) and model_probes(probe_id,profile_id,generation,identity_hash,capability,started_at,finished_at,result_json). Probe records only synthetic test result/status/usage/requested+reportedmodel, never key or modelprivatecontent. Existing profile.capabilities becomes a derived compatibility display, never authority: control config.save cannot forge it; Store config write and credential-reference commits invalidate records/increment epoch/clear capability list when any identity field changes or profile disappears. New/recreated IDs increment from retained epoch so deleting/readding cannot revive old validation. No new app_config schema needed. Capability lookup uses current generation+identity, latest completed successful probe of that capability only, with previous pass hidden after a later failure. Untested/image/stt/tts have independent states. Pure lookup/config changes do not call providers.

Explicit ProbeService runs only on user invocation with stable probe_id and positive caller-approved max_micro_usd hold. M03 already integrated in this stack: reserve a manual/unpriced conservative hold, retain labelunknown; never infer actual bill from token counts without a matching configuredrate. Fixed small synthetic text probe (reply exact nonce) or fixed valid small synthetic image+question, max_output128 and reasoningnone. These tiny probes check protocol/usable content, not benchmark quality. No actual user news/media goes in probes. Image/STT/TTS request before their adapters exists returns probe_unavailable without network/charge, not providerunsupported claim.

Persist probe intent before any paid call; use BudgetLedger reserve/begin before I/O, fresh generation check after asynchronous Keychain read and immediately beforebegin. Both records use sameStore; failure beforebegin means zero requests, an orphan reservedhold can be explicitlyreleased. Probe results and budget settlement update in one existing SQLite transaction (factor ledger settlement-in-transaction only if needed without nestedtransactions); alternatively failure afterdispatch leaves budgetinflight/outcomeunknown and never authorizes rerun. No claim crossresourceatomicity. Known200result with unknowncost settlesNone retaininghold; known error with unknownbilling retains hold, never inventzero. Definitelynotconnected can explicitreconcile0; any write/read timeout orlostresponse marksunknown and retains hold. Cancellationafterbegin likewiseunknown; no retry. SameprobeID returns persistedresult, orunknown/inprogress state, neverdispatchesagain. Resume uses existingownedstartup budgetrecover; interruptedprobe markedunknown, no automaticrepeat. ExplicitnewprobeID is a new userinitiated call counted separately.

After result, recheck profile generation/hash before exposing effectiveverifiedcapability. Changedconfigresult stays historicalstale, not attached to replacement. Keyword capability never inferred frommodelname or empty200. Text probe validates exactnonce; vision probe checks a simple known visual property from fixed image (not just accepting arbitrarytext). Success validates only that tested operation/profile at that time; futureproductionerrors maystilloccur.

Private control API adds models.status and models.probe (explicit request withprofile/capability/probeID/budgethold). Control configsave stillzeroI/O. Long probes use existing async request path; newservice owns clients and closes; no secondbackendworker or cloudframework. Request disconnect cannot auto-reissue; durableID handlesreconnect. UI exposure belongsU03, actualtaskexecutorM02 consumes adapter and verificationlookup.
