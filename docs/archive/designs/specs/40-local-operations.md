# O01 / #40 — local operations, retention and portable settings

## Frozen acceptance

Implement #40 and R10. Use the existing same-owner ControlServer, Store/SQLite, Keychain and data directory. Distinguish a live process/socket from useful current source, schedule, model, budget and outbox business health. Add a shareable redacted diagnostic projection, a portable settings preview/import that cannot replay history, and finite cleanup of safe unreferenced material. One local process, no cloud upload, no general log platform, no deployment. UI uses these private control operations through the existing mockup structure; no new settings design.

## Diagnostics

- Produce one bounded local status result with two independent sections. Process status describes the actual resident socket/worker lifecycle. Business status summarizes recent scoped schedule occurrences, source eligibility/freshness/failure, verified model slots and known fallback/unknown/blocked counts, current estimated model and X budget totals, and durable outbox confirmed/unknown/pending. Business states derive from existing tables rather than querying live providers or counting a synthetic success. Disabled or missing configuration has its own state. The detail needed for local troubleshooting can reuse existing authorized RPC views.
- A separate exportable support projection allowlists fixed status codes, bucket counts, validated timestamps, installed schema/version and aggregate capacities only. Exclude URLs, names, article/command/raw error text, credentials/references, Bot/owner/account IDs, file paths, media, budget quotes and untrusted exception strings. Map unfamiliar state to an explicit safe generic bucket. Return bytes/data to the caller only, no auto upload. Reuse private Unix frame caps.

## Backup and restore

- Keep private SQLite migration snapshots separate from portable settings. Migration stays transactional; before version bump the existing sqlite backup uses an owner-private same-install file, and failed/corrupt/full-disk attempts leave the original version/state. Add a local read-only verification for a named snapshot from the same private data directory: reject symlink, foreign/nonregular file, incorrect metadata, size or schema; bounded SQLite integrity and known supported version; The verification reports integrity/schema only, never automatic restore readiness. Only the existing transaction's rollback during a failed migration before the worker starts preserves external-effect state. A private snapshot from before a successful upgrade may predate confirmed or unknown effects; O01 provides no database replacement/restart action or ordinary recipe for it. Use the portable inactive settings path for operator restore without historical replay. Never overwrite a database via RPC, treat a migration snapshot as shareable, downgrade or mix DB and WAL generations. Test failed migration before startup and a later-confirmed send with an older valid pending snapshot, which cannot be applied.
- Portable settings format is versioned and capped. Retain relationships and non-secret preferences (locales, time zone/times, partitions, categories, Bot display aliases and routing, source settings with exportable public URLs, account handles/priority; optional non-secret budget preferences only if existing config representation safely round-trips). Export only explicit allowed model fields, prefer known provider default origin for nonportable custom endpoints and report omissions. Drop all credential references, verified identities/owner/remote numeric IDs, pairing/budget history, cached evidence, jobs, media and receipts. Treat unknown query values/private gateway paths as nonportable and omit the relevant source or reset its default endpoint; do not rewrite a URL into another effective feed without reporting. Reject credential-like hostile labels or mask them with stable safe placeholders; diagnostic export never includes any arbitrary label.
- Import first previews the exact normalized document, omitted data and inactive restored settings. Apply only to a genuinely fresh untouched instance, with explicit reviewed preview digest and current config CAS in one Store transaction. Recompute digest/shape at apply, so a changed draft or raced revision fails. Validate oldest supported format and reject corrupt/newer content, unsupported URL/relationship and nested extra credential fields. Leave schedule and all restored sources/subscriptions disabled until explicit source preview, profile verification, Bot token/verification/rebinding and subsequent enablement. No previous owner, remote post ownership, model approval or known delivery is imported. Clear special account observed identities. Never insert an outbox or require network during preview/apply.

## Retention

- Reuse bounded Store audit cleanup and keep dedup identities, cursors, budget/unknown receipts, Bot delivery tombstones and source readiness. Clean old unreferenced feed attempts/snapshots only when absent from active or historical frozen job/edition references, source-readiness and current cache references, including transactional lease/pending/unknown boundaries. Delete associations only with the selected attempt and orphan snapshots only after a second exact ref check. Never delete a ready/unknown/pending content artifact on age alone. A single private command reports preview counts and rechecks each bounded destructive batch under the Store transaction; no pathname arguments from the caller. Keep old known-state identity metadata even if body can be dropped. If X02 exists, delegate expired body cleanup to its verified local method, not a second deletion implementation.
- For normalized private media, inspect only the existing content-addressed files and matching owner/directory FD and regular-file checks. Only unlink old unreferenced images after checking exact pipeline payload and all pending/confirmed/unknown outbox/media references, conservatively preserving unfamiliar asset prefixes and versioned states. Defer the entire media unlink batch inside the write transaction while any preparing_media job holds a non-null lease, regardless of time, because existing reused asset IDs can be held in memory until final payload commit. Future asynchronous producers must declare their in-flight presence and persisted cache references before integrating with this cleanup. Stop at a finite batch and never read arbitrary outside paths. For known owned service log files expose file sizes and bounded cleanup only through existing private logging path; no symlink, stdout of another process or untrusted path. Keep unknown/pinned usage visible even when a requested cleanup cannot reclaim it. No automatic full VACUUM or service restart.

## Verification

Synthetic unavailable provider with process alive, redaction against hostile nested tokens/URLs/names and exception text, current/no-config/unknown budgets and receipts, concurrent CAS and fresh-only cross-directory restore, restore disabled/no replay, damaged/newer portable document, migration backup failure/full disk transactional refusal, old version integrity, active/referenced versus expired independent evidence, crash/orphan, old reused asset during a paused preparation callback, and malformed/symlink media, no removal of receipt/dedup or active feed cache, preview and actual bounded cleanup. No live calls or sensitive diagnostic export to GitHub. Version bump only if genuinely needed after approved predecessor.
