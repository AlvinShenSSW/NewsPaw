# F04 / #13 — Private local control and Keychain

## Frozen scope
Single owner/server/backend. Add a private Unix socket control API consumed by the later SwiftUI app, and a macOS Keychain adapter. No TCP listener, remote management, deployment, real credentials or live Bot/model test. Existing polling prototype is not cut over until T01/O01 composition. Provide an explicit foreground control-only CLI entry for setup; it does not poll/send/schedule.

Acceptance: owned 0700 directory, 0600 socket, same-UID peer verification, bounded/deadlined JSON requests, one backend writer with CAS revision. Configuration/diagnostics/errors contain no plaintext credentials. Keychain write+readback must succeed before atomic config reference commit. Failure preserves old config; durable nonsecret intent records permit orphan cleanup after crash or failed rollback. Explicit legacy .env secret import only once after Keychain available, no deletion of original file, no subscription activation or service startup. Lock/revocation errors are diagnosable without leaking provider/native exceptions. Repeated import is idempotent, failure can be retried.

## Decisions / verified evidence
Use keyring v25.7 macOS backend directly (not global backend auto-selection, never plaintext fallback). Official source https://github.com/jaraco/keyring/blob/v25.7.0/keyring/backends/macOS/__init__.py and api.py uses Security framework APIs via ctypes. set_password deletes old value before add, so always write a fresh UUID account under service io.newspaw.credentials and never mutate the prior item in place. Force keychain property None so external backend configuration cannot redirect storage. Mac backend failure/locked status mapped to fixed codes; no arbitrary repr, stdout, command argv or logs. Dependency keyring>=25.7,<26 only on Darwin; fake interface for Linux/offline tests. No real Keychain writes in default suite. Opt-in native smoke uses unique io.newspaw.tests.<UUID> service and random synthetic value, deletes only its exact test item in finally; must be explicitly enabled locally, otherwise not counted as native integration pass.

Peer identity macOS uses libc getpeereid (local Python3.13.7 socketpair probe returned current uid, no network); Linux SO_PEERCRED for CI. Fail closed if unsupported or call fails. Filesystem pathname permissions are an additional control. Same-user malicious code is outside this local ownership boundary; do not claim application identity authentication.

## Control contract
One request/response per connection, newline-delimited UTF-8 JSON <=8MiB request, deadline10s for read; response <=8MiB. The current validated config bound is1MiB canonical UTF-8, and the transport allowance covers JSON envelope and standard ASCII escaping expansion. Client canonical serialization uses ensure_ascii=False (Swift equivalent). Secret values retain the independent4096char bound; configs retain1MiB after decoding. Only exact operation field allowlists. Operations config.get, config.save(document,revision), route.preview(subscription_id,account_id?,style?), credentials.set(kind,id,value,revision), credentials.remove(kind,id,revision), credentials.status, credentials.cleanup, legacy.preferences(path,revision), legacy.secrets(path,revision). Return {ok,result} or {ok:false,error:fixed_code}; never echo request/secret/native error. No generic commands/filesystem/tool execution. Control code does not send news.

Config.save forbids client changes to credential refs or Bot verification/binding fields; those use credential operations and later T01 pairing endpoints. New Bots must be unverified/unpaired with empty identity/credential fields. Deleting an entity is allowed after normal reference validation; its old Keychain ref becomes cleanup intent. All mutations serialized by backend lock and CAS; recheck revision after credential operation before commit. Disconnected requester does not roll back a confirmed commit; reconnect and read revision/status. No mutation retry on disconnect. Same owner may inspect config without credentials; status exposes only availability codes for configured references.

Socket lifecycle: reject symlink/foreign/permissive leaf data directory, lock file opened O_NOFOLLOW owned private regular file and held flock. Only after acquiring lock may stale owned socket be removed; never unlink ordinary files or a live other server. Bind socket then chmod0600 before serving, close/unlink owned socket on shutdown and release lock. Max16 accepted connections; excess closes without reading. Async server remains bounded; synchronous credential calls serialized on one worker thread, backend DB reads/writes stay on event-loop thread. A client disconnect after sending cannot cancel an in-flight credential mutation. Keychain may prompt the user and outlive read timeout; status must say pending without claiming timeout rollback. Shutdown waits for active credential operation to settle before closing DB.

## Credential transaction and recovery
Add database schema3 credential_intents(ref PRIMARY KEY); only UUID references, never values. Existing migration transaction/backup handles v2→v3, v1→v2→v3 and version0 direct initialize. Reserve fresh refs in DB before Keychain writes. Each write reads back same value; on mismatch/error leave old config unchanged, delete fresh refs where possible, retain intents for failed cleanup. Commit new references (and legacy import marker if applicable) atomically using existing Store transaction/CAS. After commit, cleanup deletes intent-listed refs only if currently unreferenced by any profile/Bot; referenced new items are kept and intent removed. Old replaced/deleted refs become intents in same transaction as config update; shared referenced items remain. Missing item counts as cleaned. Locked or denied cleanup is explicit pending, never silently lost. Startup cleanup is safe for this process's journal only; no enumeration/deletion of unrelated Keychain entries.

credentials.set rotates fresh ref; Bot token change clears verified/paired/telegram_id/chat_id. credentials.remove clears ref and same Bot flags. To avoid unresolved cross-resource cancellation, one manager serializes complete prepare/write/readback/commit/cleanup sequence. No attempt to make SQLite and Keychain a fictitious atomic transaction: precommit errors roll back refs, postcommit cleanup failures preserve valid config and report pending cleanup. Secret input bounded4096chars nonempty/no controlchars, never stored in object repr.

Legacy import reads only explicit absolute path, regular owned file via O_NOFOLLOW, <=64KiB and not group/world-readable; no implicit env or interpolation. legacy.preferences wraps existing explicit once-only importer/CAS and normalizes old owner0 to unset (F01-K02). legacy.secrets reads only TELEGRAM_BOT_TOKEN and OPENAI_API_KEY from one read snapshot; maps model key to normal_primary, adds stable legacy_bot unverified/unpaired with no assignments. Existing destination credential refuses overwrite; no secrets found returns no effect. Separate legacy_secrets_imported marker permits preference import before/after secrets (but no overwrite of edited preferences). Only a legacy-secret commit on a currently preference-import-eligible revision advances untouched_import_revision to its new revision, atomically. The eligible preference importer preserves already-committed model credential references by stable profile ID and existing unassigned legacy_bot while importing nonsecret preferences; validate merged result before commit. Generic edits/credential rotations do not advance eligibility. No previously edited/paired/assigned Bot can meet this untouched eligibility through normal APIs. Repeated successful secret import returns already_imported with no Keychain writes. Failure doesn't set marker. No provider model verification asserted by successful Keychain storage.
