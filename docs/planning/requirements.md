# NewsPaw 实施需求基线

版本：2026-11-07。优先级：本文件补充既有产品文档并解决边界歧义；后续用户明确变更优先。`backlog.json` 和 GitHub issue 描述具体工作范围，issue 必须冻结后才执行 AFK。

## R01 界面与运行

沿用 `docs/mockup/newspaw-settings.html` 的五页界面、选定 Logo 和统一图标，不重做视觉设计。SwiftUI 原生菜单栏 App，配置窗口关闭后后台继续；退出 UI 与停止后台分别可操作。正式程序不依赖开发目录、全局 Python 或用户手装 ffmpeg。macOS 13+、Apple Silicon 为首版实施目标；Intel 支持另行验证，不提前承诺。数据在用户 Application Support；后台单一配置写入者，通过私有 Unix socket 提供版本化控制接口。

## R02 分类、订阅和优先级

世界时政、日本/澳洲/中国国内与娱乐、数码新品/突破、AI 模型/Skill/Repo、AV 产业、X 普通与成人分区。娱乐不是自动成人；供应商名也不决定分区。source 与 category 多对多但不可跨分区复用原文；subscription 才拥有计划、选稿与目标。国内/娱乐可调权重和条数，用户需要不同时间或 Bot 时可显式拆分订阅。

有效配置：本次明确样式选择 > 特别账号覆盖 > 订阅/分类 > 所属组默认；新闻输出语言始终全局。源继承订阅，不拥有隐藏时间/Bot。账号普通/特别关注与内容普通/成人是独立维度。新源或账号必须明确分区才送任何模型。分区变更使不兼容缓存和未发送任务失效，禁止将旧普通摘要复用为新成人稿或反向复用。

## R03 来源与证据

优先 RSS/Atom/正式 API，再已适配网页；未知网址只保存草稿。目录、粘贴网址、OPML、GitHub、HF；X 地址转 X 管理。试采集不推送。推荐源记录实际连接方式、健康/新鲜度/覆盖、依据日期。CNN、Yahoo Japan、联合早报是用户点名来源；无法取得全文就明确只读摘要/发现页。AV 已知 fiu758.com，第二站未知。保留原出版商、URL/ID、发布/更新/抓取时间、来源语言、证据范围与哈希，严格拒绝无时区/未来/过期候选进入新鲜新闻。可用旧证据作标注日期的背景。

URL 检查覆盖 DNS、重定向每跳及实际连接，禁止私网/回环/链路本地与凭据 URL；不得把模型 Key 随重定向发送到其他 origin。控制超时、响应大小、解析复杂度、分页与重试。文章和 SKILL.md 是数据，不执行里面的指令、代码或安装动作。网页补证的搜索提供商独立配置并记录；未配置时只用已可用来源，不虚构“已搜索”。

## R04 模型、费用与语言

普通 GPT-6 Luna `gpt-6-luna` 主 / MiMo Flash `mimo-v2.6-flash` 备；成人 DeepSeek `deepseek-flash` 主 / Grok `grok-4.3` 备。每槽独立 URL、Keychain 引用、模型、协议、能力验证；分类可在同组覆盖。文字、视觉、转写、TTS、生图能力分别登记，不假定文字备机支持媒体。仅临时/配置错误按明确策略有限重试及同组切换；内容拒绝不用于跨服务绕过。模型无法改接收者、执行 shell、读任意文件或突破任务范围。

预算按任务预留→调用→结算，主备、格式修复、生图纠错共用总额；X 消费独立展示但有自己的总量/分区/账号约束。未知价格/用量不伪造实际账单。到限保留任务及覆盖缺口。

UI locale 与 news_output_locale 分别为 zh-Hans/en/ja。全部最终标题/摘要/冲突说明/报纸/播报使用输出语言，原文只在证据中展示。更改 UI 不改任何订阅；更改输出语言使未发旧版本失效。无法得到合格目标语言正文则等待/失败，不能自动发原文顶替。

## R05 编辑与去重

先 URL/帖子 ID/内容哈希去重，再同分区事件归并。保留来源冲突、转载链、传闻/专利/原型/量产以及个人声明归因。条数是上限，少报胜过编造。AI 新闻区分公告、API 上线、开放权重、许可证与可用性；repo/skill 看实际变化，不执行仓库指令。按订阅/期次区分投递去重；世界发过的事件仍可进入日本期次。后续补证和事件更新不把旧内容当作新发布。

## R06 X

稳定账号 ID、用户名变更/停用、原帖/引用/回复/转发开关；按账号固定时间特别日更和按分区定时汇总。默认特别账号不再进入合并简报，可显式双报。timeline 增量分页先落库后推进完整游标；中途预算/限流/重启保留缺口。List 不假设 since_id，成员变化先分类；未分类成员原帖不交给普通模型。公开 List 整体成人可整流成人；普通 List 新成员等待确认。不会因为 Grok 可处理内容就用搜索接口冒充 X 完整 timeline。总/分区/账号读量持久化，共享证据但不共享跨分区上下文。

## R07 时间与队列

每个分类/拆分订阅/特别账号拥有稳定计划槽、IANA 时区、独立时间。目标时间是推送时间，预采集与准备有明确 lead time；错过不伪装准时。默认东京、补最新一期、6 小时补发建议；用户设置覆盖建议。DST 跳过时顺延、重叠时一次；更改时区/时间不重发完成期次。睡眠/离线/崩溃恢复和多 worker 抢占均有持久化 lease 和唯一约束。

采集→证据→冻结简报→媒体→outbox，各阶段可恢复且不重做已成功收费步骤。投递键 subscription/edition/bot/chat/part；确认未知为独立状态，默认不盲目重发。每次副作用前重新检查暂停、绑定、路由与版本。语言/分区变化：未发重建，部分已发停止剩余并提示人工选择；不能混语言或迁移旧部分到新 Bot。

## R08 Telegram

多 Bot 各自 token、getMe 身份、同一主人的私聊配对、游标与限流；重复 Bot ID 和 webhook 冲突可见。短时一次性配对码、限次、无日志明文。无目标/暂停/未配对不发送；同一简报多目标只生成一次，各自回执。成人目标显式选择，不继承普通目标。删除/解绑立即停止未发，保留历史，不换 Bot 兜底。

聊天权限精确到当前 Bot 分配的订阅或特别账号。自由文字/图片/语音先确定范围，再调用对应模型；混合 Bot 或范围不明先让用户选分类，不把内容先交普通模型来分类。回复新闻沿原 brief 的分区和权限；查找/解释/制作报纸均复验授权。查询、计划、暂停、状态和 /why 可在范围内操作，Key/Token 仅本机。管理回复跟随 UI locale，简报和正文跟随 news_output_locale；来源名/账号不翻译。

## R09 多模态

默认文字+链接且不自动附图；来源配图按范围选择，保留来源/署名，失败用已校验文字。成人媒体自动预览关闭。指定新闻可生成 1–2 张真实 AI 生图报纸；稿件先冻结并翻译，再分页面生成、OCR/同分区视觉核验、附外部可点击来源与 AI 示意标注。未配置能力/质量差/预算不足降级合格文字，不能迟到后自动补图。语音/图片提问仅是线索，媒体大小时长受控并清理临时文件；能力不支持时要求文字，不静默丢输入。

## R10 交付与运维

设置/任务/预算/源健康/模型切换/投递状态可诊断并脱敏导出。保留策略不会删除仍被待发任务引用的证据；清理媒体、日志、墓碑与回执各有边界。迁移前备份，失败回滚，旧版禁止写新版 schema。配置导出无凭据；导入先预览，不自动开启订阅；恢复后 Bot 重验/重新绑定，不重放历史 outbox。签名、公证、安装、升级、卸载与登录项控制各有验证。CI 分开离线单测、契约/故障注入和 macOS UI/打包检查，真实付费联调须独立启用。

## R11 开发约定

Codex 主导；Kimi K3.1 Pro 独立外门并作为本轮最终审阅。单一 Kimi 外部角色，不用 Codex 审自己的实现；指定型号不可用时明确报告，不静默换型号。沿用 AFK 1.3.7 流程但只执行用户交付的明确 issue 范围；创建 backlog 不等于启动整库开发。默认 PR leave-open，不自动部署。epic 是协调范围，优先逐个子 issue 形成可评审 PR；依赖满足且验收冻结后才执行。
