# S03 #16 — AI model and repository evidence connectors

## Spec review / frozen issue contract
Provide public GitHub Releases and relevant-file updates, Hugging Face model cards/revisions, and official vendor announcements as evidence for existing news editing. Single owner/backend/SQLite; no installing, importing or executing source projects. A repository without Releases must still yield relevant README/SKILL changes; conservative pure-format changes can be filtered. Store immutable commit/release/model identifiers, license (unknown if absent) and observed availability. Never equate announcement, metadata listing, file existence or gated weights with a working public API or downloaded weights. Source text is untrusted data, including instructions and code in README/SKILL. No Stars-only ranking, investment suggestions, inference, downloads of model artifacts, private sources/auth credentials, generic plugin framework, UI/scheduler/Telegram work. Existing mockup and model partition controls unchanged.

## Acceptance / decisions
- Existing configured source kinds `github` and `huggingface` become collectable with the same source/subscription/partition/configuration revocation rules as S01. Explicit preview requires source ID; subscription collect skips other connector kinds, preserving explicit unsupported preview errors. Disabled sources do not run. All persisted evidence has source association and explicit observed event timestamp, fetched timestamp, raw dates, scope, stable version and availability provenance.
- GitHub source URL: `https://github.com/owner/repo`, or `/blob/<single-segment-ref>/<path>` for a specific README/SKILL file. Root watches README.md and SKILL.md on default branch and Releases. Explicit file watches that one path (arbitrary text path allowed, never executed); refs with slash require SHA form. Reject extra query/fragment/credentials and unsafe path components before network. Root scope does not claim automatic discovery of every nested skill; add explicit file sources for those.
- Public unauthenticated GitHub REST, API version 2026-03-10. Repository info provides stable ID, canonical full_name, default branch, current license (not falsely historical license). Follow bounded same-origin redirects. Pin first observed remote ID in one small connector state row keyed partition/kind/configured URL; a later different ID is identity_changed, never silent rebind. Rename with same ID accepted; preserve configured and canonical URL separately. 404 means not_found_or_private, not proof of deletion. Branch/tree/content mutations never performed.
- Release list: 30/page, max3 pages; published_at is event date, created_at separately metadata, draft skipped, prerelease marked, id/tag/body retained with bounds. Follow Link next only if same origin and expected endpoint, cycles rejected. Reaching page cap or errors after prior pages preserves candidates with explicit coverage gap; no false complete result/high-water advance. No release is normal empty, proceed to watched files.
- File updates: query path-filtered commits (latest bounded30, max3 pages); evaluate relevant commits in current freshness window with per-source request ceiling60 and total wall deadline60seconds. For each, get immutable current file and first-parent file by commit SHA; compare normalized CRLF plus trailing whitespace only. Preserve indentation, Markdown punctuation and executable text as data; only equal normalized content filters an event. Missing parent/unavailable comparison retains candidate with explicit limitation. File deletion (current404,parent exists) is explicit deletion evidence; both missing becomes coverage gap, not invented content. Each candidate records SHA/path, commit message/excerpt (bounded), parent SHA and event committer date plus author date separately. No stateful suppression/high-water mark needed: bounded recent snapshots and M04 event versions handle repeats. If budget/page/time limit truncates history, surface gap. This avoids a new cursor/replay subsystem.
- Hugging Face: source `https://huggingface.co/owner/model` or `/models?author=<owner>` only. Listing uses documented model API full/cardData data, sort lastModified (raw REST spelling verified against upstream client before implementation), 10/page max3pages, max10 model details/cards per run; limits visible. Single model fetch metadata + README at returned immutable SHA. Listed siblings may establish weights_listed; gated auto/manual/unknown recorded; API availability always not_verified, no inference requests. Missing license unknown. Create event uses createdAt; revision event uses lastModified explicitly labelled repository revision, preserves original createdAt and never calls a timestamp update a new model launch. Card metadata and bounded text are retained; no YAML object construction/executable tags, no arbitrary extra JSON. Missing card remains metadata evidence with gap; model404not_found_or_private. Models/repo paths generated from validated IDs, not arbitrary returned download URLs.
- Official announcement catalog entries use existing RSS/Atom collection (OpenAI news, Hugging Face blog); connection URLs marked candidates until preview validates, never marked proven operational from a web content-type failure. Catalog annotation distinguishes publisher announcement and unverified actual availability. S04 will extend broader catalogs and source UX. No live model endpoint verification here.

## Approach / data flow
Reuse S01 evidence snapshots/attempts/associations/recovery; no new parallel evidence ledger. Add optional allowed-kinds parameter to `_source`/`_selection` with RSS/Atom default; stored API scope carries allowed kind and evidence_scope. `current` reads scope kinds with backward default; `finish(cache=False)` stores API snapshot without touching RSS conditional cache. Existing RSS calls unchanged. Health/history accept known RSS/API kinds, preserving partition/key checks. Connector state table schema9 holds only stable remote identity/canonical URL, updated transactionally only with current scope and successful attempt; safe idempotent schema upgrade + rollback.

Article gains optional metadata dict and evidence_scope default rss_excerpt; old snapshots decode via defaults. Metadata comes from allowlisted typed bounded fields in our adapters; no raw response dump. Content hash includes metadata only when present so old RSS identities remain unchanged. Model/event IDs and URLs are local constructions from validated API fields. Dates require timezone; missing/invalid dates kept visibly ineligible using S01 filtering, never replaced by fetch time.

`AICollector` shares S01 selection/lifecycle and one guarded HTTP client; handlers in connectors/github.py and huggingface.py return articles, coverage gaps, stable identity changes. Public HTTPS/DNS/size/deadline guards from F03 apply every hop; no process/environment credential lookup. Each request <=2MiB, card decoded <=256KiB, title<=500/excerpt<=1500, max200 candidates, JSON depth/field/value bounds enforced through typed extraction; malformed API data fails visibly without raw body logging. Each source60requests/60seconds, redirects<=3 and pagination<=3. Rate errors403/429 produce rate_limited + Retry-After if present, no hidden retries. Cancellation records cancelled and propagates; restart uses existing interrupted recovery, no automatic replay. Partial valid pages survive later failures with coverage_complete=false; no partial data falsely labelled all-source failure. SQL failure rolls back snapshots/identity/attempt completion together.

M04 pool passes allowlisted metadata/evidence scope to model and retains source/event date provenance in structured output. Keep fixed localized event labels for commit/release/model_revision (no raw untranslated commit titles automatically published). Copy coverage_complete/gaps; renderer counts incomplete coverage even when candidates exist. This is narrow integration so new source kinds actually feed existing editor; no new paid pipeline entry or unsupported independent corroboration claim. Existing RSS snapshots/model requests remain compatible.

Sources: https://docs.github.com/en/rest/releases/releases ; https://docs.github.com/en/rest/commits/commits ; https://docs.github.com/en/rest/repos/contents . Raw REST parameter spelling/pagination and SHA README retrieval to verify from official client source before code; if unavailable record API source unverified and do not fake live success. No actual live account access tested. Vendor RSS content-type observed by web tool but feed body not verified; presets candidate status. Conservative whitespace equivalence deliberately does not promise semantic equivalence of arbitrary Markdown.

## Risks and validation
API schema change/rate limits: bounded typed parsing, partial coverage and explicit errors. Renames/reused paths: stable ID mismatch regression. Untrusted Markdown: no execution, no install, excerpts untrusted in M04 instruction. No credential propagation. Old snapshots: defaults, unchanged RSS hashes. Partial storage: transactional fault/reopen tests. Event timestamps: separate original creation/update/commit event basis, test no fetch-time substitution. Model API/weights availability: unknown unless directly observed metadata, never inferred active service.

Tests-first fixtures: no-release repo still detects SKILL; nested explicit file; meaningful vs whitespace-only changes; deletion and missing parent; paginated releases/commits and rate failure after first page; malicious pagination/redirect; repo rename/sameID and replacement/differentID; absent license; HF gated/listed weights+missing card/date+new model/revision; bounded malicious README containing shell instructions and external secret URLs never executed/fetched; cross-partition sharing isolation; config changes during fetch; cancellation/reopen/SQL rollback; old RSS cache/hash compatibility; API evidence -> M04 metadata/coverage localized render. No live paid calls or messages. Full local suite and actual Linux/macOS CI, internal review, Kimi sole gate before merge.
