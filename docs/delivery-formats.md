# 新闻推送样式与 AI 报纸

状态：已确认需求的目标设计，尚未接入后台、图片生成 API 或真实 Telegram 推送。本文与设置预览不代表已经生成新闻图片。

## 三种样式

| 样式 | 适用范围 | Telegram 收到什么 |
| --- | --- | --- |
| 文字与链接 | 默认，适合大多数新闻 | 标题、简短摘要、来源与发布时间、可点击原文链接 |
| 来源配图 | 选择需要图片的分类、账号或单条新闻 | 相关来源图片及署名，加文字摘要和可点击来源；无合适图片时保留文字 |
| AI 报纸 | 仅对明确指定的分类、账号、专题或单条新闻启用 | AI 总结后通过生图功能制作的 1–2 张报纸图，加文字概要和可点击来源 |

默认全局样式为文字与链接。分类可覆盖样式；账号可覆盖所属分类。特别关注只决定是否单独日更，不自动启用配图或生图。用户在 Telegram 回复某条简报并选择“制作报纸”，可只为该次内容生成报纸，不改变持续订阅设置。未来可提供等价 `/paper` 命令，范围限定为回复的简报或明确的条目 ID，不能凭一个模糊标题生成未经采集的新闻。

样式优先级：本次明确选择 → 账号设置 → 分类设置 → 全局默认。页数独立设置为“自动 / 1 张 / 2 张”，上限始终为 2 张；自动优先一张，内容确实需要且预算允许时才扩为两张。持久的专题规则必须由用户明确建立，不能由模型自行扩大生图范围。

样式与 [目标 Bot 分配](telegram-routing.md) 独立：一个分类可发给多个 Bot，特别关注账号可单独覆盖接收目标；选择报纸不会改变 Bot。相同冻结报纸发往多个目标时复用图片，每个 Bot 分别记录回执。

成人分区默认保持文字与链接，关闭原始媒体自动预览。用户选择报纸样式时，仅制作非露骨的行业报道与动态摘要，保持成人模型与媒体处理路线隔离。

## 来源配图

配图来自已采集证据中的相关媒体，并保存原始媒体 URL、出处、对应条目、可用署名和使用条件。不会将无关图库照片配成现场照片；不能确认关联或无法取得适合使用的素材时，退回文字。转载、截图、图表和新闻现场照片分别标注，图片本身不能替代文字证据。

没有来源配图时不自动调用生图，也不为找图片增加 X 历史抓取；如需要额外媒体读取，遵守已经设置的账户和分区预算。来源配图的启用不打开成人图片自动预览。

## 报纸的制作流程

1. **冻结证据。** 复用本期已采集的来源、时间、冲突说明与内容分区，不为了制作报纸重复抓取同一批 X 帖子。时间未知或证据不足的内容仍遵循原来的入选规则。
2. **先完成编辑稿。** 对应的文字主备组整理标题、导语、要点、背景、来源编号和需要保留的不确定性，翻译到 `news_output_locale`，校验引用。此稿是图片与随附文字的共同依据。
3. **制定 1–2 页版面。** 一页适合一则重点事件或少量短讯；两页可分为“重点与发生了什么”和“背景、时间线与影响”。选择少量清楚的内容，避免靠极小字号塞满全文。不够内容就一页，不凑版面。
4. **调用图片生成能力。** 将已批准的逐字文案、版式要求、目标语言和允许的插图说明交给对应生图主用模型；需要时使用同组备用。两页使用分别冻结的页稿与共同版式，每页独立生成，不把一次请求两张图片当作有保证的连续分页。真正输出图片文件，不能把 HTML 截图冒充生图结果。
5. **检查图片。** 检查标题、正文、专名、数字、日期、来源编号、页码、目标语言与手机阅读效果。OCR 配合具备图像理解能力的同分区校验器比对冻结编辑稿；能力未配置或无法确认时不能标记“校验通过”。发现错字、缺段、数字错位或新增无证据断言时，有限次修复，仍不合格则改发已校验的文字。
6. **投递图片与来源。** 一张发单图，两张按页序组成相册；同时附上简短文字概要与完整可点击来源。来源列表较长时拆为独立文字消息，不能只把链接画在图片中。可提供原图文件，便于保存和查看小字。

生成插图明确标为 AI 示意图。源站真实图片与生成插图区分，不生成或包装成真实新闻现场照片。报道中的未知、传闻或分歧不能因视觉表达而变成确定事实。报纸图片可以使用报头、分栏、插图、时间线和信息图，但所有新闻断言都必须来自冻结编辑稿。

默认建议采用适合手机阅读的竖版：大标题、清晰导语、少量分栏、醒目的图片、底部来源编号与期次时间。英文、日文、简体中文分别排版；不能只翻译标题却保留另一种语言的正文。确切像素尺寸按实际图片模型支持的参数选择。

## 生图模型与语言

生图是独立能力，不能因为文字模型能看图片就认定它能生成图片。保留已有四个文字模型的主备默认值，另设：

- 普通生图主用与备用：各自的 API URL、API Key 引用、模型 ID、适配器及图像能力验证结果。普通主用按 OpenAI 图像 API 方向接入；具体图像模型与备用尚未选定，保持未配置，不自动复用 `gpt-6-luna`。
- 成人生图主用与备用：独立配置、独立验证，不将成人上下文交给普通生图或普通视觉校验服务。DeepSeek Flash / Grok 4.3 仍是已确认的文字处理模型，其名称不能直接填成生图模型。
- 图像理解校验为单独检测的能力，可复用经过验证的同分区模型；没有可用校验器时，停留在待检查或降级文字，不能跳过事实核验。

每个图像槽位同样支持 URL、API Key、模型的独立设置；密钥保存在 Keychain，不出现在导出、提示词记录或日志中。普通与成人的主备切换、预算、拒绝响应遵循 [模型路由规则](model-routing.md)。接口兼容性与账户权限须真实验证，不能仅凭填写了 URL 判定就绪。

图片全部文案使用默认新闻输出语言，包括报头说明、日期格式、图例、插图标签和随附摘要。来源名称、账号与产品编号保留正确写法。App 显示语言不影响图片。切换新闻输出语言时，尚未投递的报纸须重新排稿、生成与校验；预算不足时发送新语言文字，不发送旧语言图片。已经送达的历史报纸不自动重做或重发。

## 费用、失败与重试

生图预算单独显示，且受总模型费用预算约束；区分正常生成和纠错尝试，所有尝试都计入预算。默认不启动任何生图任务，只有明确选择报纸样式并完成配置后才生成；一份报纸最多两张，不承诺每次任务只产生两次收费尝试。

图片缓存键包含编辑稿版本、新闻输出语言、内容分区、版式版本、页数、实际模型与配置版本。记录图片生成方式、校验结果和事实来源，便于审计与重新制作。Telegram 重试复用已验证的图片，不重新付费生图。

图像能力未配置、请求超时、预算不足或质量检查失败时，优先按时发送已经校验的目标语言文字与链接，并标明本期报纸未完成。可在 App 查看原因并手动重试；不在文字已送达后自动追加一份迟到报纸。若缺少的是合格文字稿，沿用简报任务失败处理，不直接转发原文。

图片、相册和来源文字分别记录投递状态，作为同一期报纸的不同组成部分。部分成功只重试未完成部分；网络超时导致结果未知时保留不确定状态，不能宣称严格恰好一次。

## 验收重点

1. 新订阅默认文字与链接；特别关注不会自动生图；原来的“允许配图”设置不迁移为报纸。
2. 单条“制作报纸”不改变账号或分类；账号覆盖不改变其他账号；两页内容按正确顺序发送。
3. UI 为英文、输出为日文时，图片和随附摘要均为日文；切换语言不能沿用旧图片。
4. 图片的数字、日期、名字与编辑稿不符时不能自动发送；修复或模型切换有界并计入费用。
5. 缺少生图模型、来源图片或预算时，文字与链接仍能正常送达；未取得合格正文时不能用降级绕过。
6. 发送重试不再次抓取 X、不重新生图、不混入另一个内容分区；图片内的来源编号可对应到随附的可点击链接。

## 接口依据

以下为 2026-11-07 官方文档核对，未调用付费接口或验证用户账户权限：

- [OpenAI Images API](https://developers.openai.com/api/reference/resources/images/methods/generate)：可直接指定图片模型；首版建议按冻结页稿分别调用。多个输出数量并不等于已经编排好的多页报纸。
- [Responses 图片生成工具](https://developers.openai.com/api/docs/guides/tools-image-generation)：工具编排模型与实际图片生成能力需要区分，不能把文字模型 ID 直接当作 Images API 的图片模型。
- [图片生成的限制](https://developers.openai.com/api/docs/guides/image-generation#limitations) 与 [提示词指南](https://developers.openai.com/api/docs/guides/image-prompting)：不能保证逐字排版与精确布局，因此最终图片需要校对。
- [Telegram sendPhoto](https://core.telegram.org/bots/api#sendphoto)、[sendMediaGroup](https://core.telegram.org/bots/api#sendmediagroup) 与 [InputMediaPhoto](https://core.telegram.org/bots/api#inputmediaphoto)：单图与相册分别投递；图片说明的长度有限，完整来源可放在后续文字消息中。相册本身不支持直接附加 `reply_markup`，需要操作按钮时另发文字消息。
