# U01 / #33 — native NewsPaw settings shell

## Frozen contract

Build a real SwiftUI settings application and menu bar item using the approved layout, paw/newspaper logo, abstract female category icon, and five current pages: Subscriptions & Sources, X Accounts, Models, Delivery & Service, and Language. Show actual local backend state, including a clear disconnected state. Independent Simplified Chinese, English and Japanese UI and news output choices. Closing the window leaves the app menu and backend available; quitting Settings and stopping the backend are distinct. Navigation and primary controls usable with keyboard, VoiceOver and light/dark appearance. Build and test on Mac, inspect actual window/menu with isolated backend. Existing mockup stays unchanged.

U01 delivers the native shell and read-only real lists plus language editing and backend stop. Source/Bot management U02, model/budget editing U03, X editing U04, automatic launchd/O02 packaging, and actual scheduling/delivery are separate. No copying mockup HTML into a web view. No fabricated sample subscriptions, tokens, models, Bots or health status. No running or modifying the user's existing service during tests.

## Design and authority

- Add a dependency-free macos/NewsPaw Swift package (macOS 14+) with a native app target and XCTest target. Build a local development .app under ignored build output with standard bundle metadata and its resource bundle; do not install or sign a release. Reuse existing logo preview and abstract female preview as byte-identical bundled resources. Keep a native light/dark adapting sidebar, two-column category card grid that fits to one column, readable scrollable page content and native window chrome. Use SF Symbols with the same categories as current mockup; supplied female line icon uses the same accent as other symbols. Brand artwork keeps white ground as approved. No new visual identity.
- SwiftUI Window and MenuBarExtra share one main-actor observable model. Window close never signals backend and AppKit delegate keeps the app alive without its settings window. Menu bar provides show window, refresh, connection status, quit settings, and clearly separate Stop Backend. Standard keyboard shortcuts and native selected list controls. Buttons have semantic labels; section headings and statuses use VoiceOver text, not color-only meanings. Use accessible contrast, system text and flexible width/scroll rather than fixed text line limits. User-visible copy in all three locales. Use a typed small localized string table for the shell and dynamic config labels only where known; user-entered names/handles are preserved.
- Read the current F04 same-UID AF_UNIX control socket, default matching the Python CLI's ~/Library/Application Support/NewsPaw/control.sock. Use a single bounded request/reply client, nonblocking connect/read/write with overall monotonic deadline, newline JSON frames no larger than existing 8 MiB, verify getpeereid equals the app's effective UID before data, reject invalid path/frame/wrong peer. No TCP, arbitrary remote addresses or shell command execution. Run blocking native socket operations off the UI main actor; bounded completion even for unresponsive daemon. For UI verification only, a generated development bundle can name a disposable socket. Do not write production data or secrets.
- Add narrow service.status and service.stop operations to existing private ControlServer. Status returns running/stopping and protocol version. Stop is explicit same-UID local action: set server stop request, send acknowledgement, serve_control exits via existing drain/cleanup and releases the process lock. No launchd changes, installation or starting another daemon. Reject mutations once stop is underway. Status is separate from Telegram connectivity. Swift polls status/config and current bots.list with visible offline/stopping/error distinctions, clearing operational state on disconnect. Store no real credential, chat ID or full configuration locally; the real backend owns those records. No raw backend errors in UI. Read only fields needed for the five pages, display a fixed message if a list is unavailable. A failed or malformed response does not mean connected/healthy.
- Language page uses independent pickers. Local display language is persisted to UserDefaults; first connected launch can initialize it from backend ui_locale if no local choice exists. If connected, an explicit UI choice also updates the backend ui_locale for local management replies through its existing revision-checked config.get/config.save; if backend update fails show a scoped error and do not change news locale. Offline display choice stays local; no silent write on reconnect. News output language comes from backend news_output_locale and is editable only while connected. Fetch fresh config, mutate only the intended locale field, preserve unknown fields and submit exact CAS revision. On conflict refresh and surface it; no blind retry. Strings shown for disconnected views do not claim to be real configured news settings.
- Subscription page lists actual categories/active subscription status and configured sources; X page splits ordinary/adult/unclassified and highlights actual special accounts; Models shows active configured provider/model slots and current capability projection, without claiming credential verification based on name; Delivery lists actual Bot registration/pair/pause state and service controls; Language shows independent choices. Display clear empty and unavailable states. Actual editing outside Language/lifecycle is later issues, no demo controls.
